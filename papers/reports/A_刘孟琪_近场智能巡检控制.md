## 2. 一句话结论

**这是一篇"控制器写得很完整、验证写得很薄"的控制学科硕士论文**：第二章的巡检路径几何与成像参数推导（`d = W_bmax/(2·tan(半视场))`、覆盖宽高反算）是五篇里唯一有完整闭式链条的一块，但**它的角度与距离数字内部不自洽**；第三/四章的 EKF 与改进 NMPC（避障项 `J_obs` + 控制增量惩罚项 `J_u`）是标准教科书写法加两个目标函数项，**因为 M4T 走 KMZ 预下发航点、机载不控轨迹，整章对 wt_inspection 不可迁移**；第五章的仿真**没有实物、没有真实图像、没有真实传感器数据**，且论文自述「EKF 与 NMPC 在仿真里未接通」——四个贡献里有两条是平行独立仿真的。**真正值钱的只有两条**：表 5-6 给出的「安全阈值设成目标值 → 实际距离欠账 0.35 m」的定量形状，以及「最近点 → 分区 → 中心线投影」这个**不需要任何图像**的相机指向方案。另外，**全文假设风机停机却从未声明**，叶尖坐标是给定常数，轮毂定位自述「假设已知」。

## 3. 绪论与研究定位（PDF 页 10–21，印刷页 1–12）

### 3.1 问题设定

作者的靶子是「**远距离巡检**」而非「有没有巡检」：

- 引 Su J. 等人的工作作为直接对照：该方法先采全景视图识别叶尖 → 理论计算生成巡检路线 → 碰撞检测 → 实景试验，但「测量坐标与真实坐标之间存在 **2 米的误差**」，且「精细化巡检时，无人机与叶片需保持 **10 米的距离**」（印刷页 8）。作者认为这个距离太大，故提出「**近场**」路线。
- 近场的代价作者自己点明了：**要与叶片保持安全距离 → 图像清晰度不够 → 细小损伤识别不准**（印刷页 4）。作者的解法是**在安全距离内把相机对准做稳**（相机对准控制器）+ 路径设计保证覆盖，而不是提高分辨率。

### 3.2 作者自述的四个贡献（摘要，印刷页 i）

1. 一体化近场巡检路径规划：**12 条主要巡检路径** + 「计算量低、通用性强」的路径生成算法。
2. 基于 EKF 的多传感器融合状态估计（IMU/GPS/高度计/磁力计）。
3. 改进 NMPC：目标函数中**创新性引入避障项和控制输入变化量惩罚项**；结果声称「与风机始终保持 **2 米**的安全距离」。
4. **相机对准控制器**：结合 EKF 与 NMPC 的信息实时算云台角，解决「镜头偏移」问题。

### 3.3 与 wt_inspection 的定位差异（先给结论，细节见 §9/§10）

| 维度 | 本文 A | wt_inspection |
|---|---|---|
| 执行体 | 自研四旋翼 + 机载 NMPC 实时控轨迹 | DJI M4T + 妙算3，走 KMZ/wpml **预下发航点**，机载不控轨迹 |
| 安全保证 | **在线**（NMPC 避障项，靠仿真调参） | **离线**（解析安全校验 + 危险航段修补，落盘前拒收） |
| 覆盖对象 | 塔筒 + 叶片（含前缘/后缘/迎风/背风） | 叶片为主 + 塔筒段（转动模式下塔筒段整段跳过） |
| 相机 | 禅思 H20 广角，等效焦距 4.5 mm，DFOV 82.9° | M4T 自带相机，等效 35 mm 画幅换算 |
| 验证 | MATLAB 仿真，无实物 | 设备上装 dpk，已跑通真机链路 |

**一句话**：A 篇是「控制学科的自研飞行器方案」，其**方法论主体（NMPC/EKF）无法迁移**到 M4T+PSDK 上，但它的**几何与成像参数推导（第二章）**是四篇里最完整、最可迁移的一块。

## 4. 第二章：巡检路径规划（PDF 页 22–31，印刷页 13–21）

### 4.1 相机选型与巡检距离（§2.2）

选型：**禅思 H20 广角模式**（表 2-1，PDF 页 23）——分辨率 1920×1080、1/2.3" CMOS、30 fps、DFOV **82.9°**、重量 678±5 g。作者的理由是广角换覆盖范围、缩短距离补清晰度，同时降低数据量。**注意：这是挂载云台相机，与 M4T 自带相机不是一回事，参数不可直接搬。**

论文给出的传感器尺寸 **7.53 mm × 5.64 mm**、等效焦距 **4.5 mm**，由此：

```
HFOV = 2·arctan(W/2f) = 79.4°          (2-1)
VFOV = 2·arctan(H/2f) = 66.2°          (2-2)
```

风机尺寸（表 2-2，PDF 页 23，印刷页 14）：叶片最大宽度 `W_bmax = 2.1 m`、叶片长度 `L_b = 39.22 m`、塔筒高度 `H_t = 70 m`、**塔筒直径 `D_t = 1.7–2.7 m`**（OCR 把这一行丢了，已从 p023 原图订正）。

最小巡检距离（式 2-3，印刷页 15）：

```
d_min = W_bmax / ( 2·min[ tan(HFOV/2), tan(VFOV/2), tan(DFOV/2) ] )   (2-3)
```

结果 `d_min = 1.68 m`，加安全裕度后**取巡检距离 `d = 2 m`**（塔筒与叶片通用）。覆盖率：

```
W_h = 2d·tan(HFOV/2) = 3.35 m          (2-4)
W_v = 2d·tan(VFOV/2) = 2.51 m          (2-5)
```

⚠️ **算术自查（[V]，我按原图数值复算）**：把 W=7.53、H=5.64、f=4.5 代回 (2-1)(2-2) 得 **79.8° / 64.1°**，不是论文印的 79.4° / 66.2°。而 1.68 / 3.35 / 2.51 三个数字都与「比值形式」`sensor/(2f)` 严格自洽（5.64/9=0.6267 → 2.1/(2×0.6267)=1.68；2×2×7.53/9=3.35；2×2×5.64/9=2.51），与印出的角度不自洽。⇒ **论文里「打印的角度」与「算出的距离」来自两套略有出入的数据（角度疑似直接抄 DJI 规格书，传感器尺寸/焦距是反推的），混用引入约 2° 误差。** 迁移时不要照抄角度，要照抄 `d = W_bmax/(2·tan(半视场))` 这个**判据形式**。

> **对 wt_inspection 的意义**：`d_min` 的推导形式与 `wt_camera.c` 的等效画幅 GSD 换算是**同一件事的两个方向** —— 论文是「给定叶片宽度和视场角 → 求最小距离」，项目是「给定距离和画幅 → 求 GSD/覆盖宽度」。两者可以互相校验。**但论文用的是 1/2.3" 传感器 + 4.5 mm 焦距的 H20，项目用 M4T 相机，数字绝不能搬。**

### 4.2 风机几何特性与简化（§2.3.1）

- 塔筒：规则圆柱，半径沿高度渐变（1.7–2.7 m）。
- 叶片：两个半壳、三维曲面，需要覆盖迎风面/背风面/前缘/后缘。
- 轮毂：「形状突出，在实际巡检时需要特别注意避让」。
- **简化策略（关键）**：因为「改进后的 NMPC 算法具备实时避障功能」，所以**路径规划时忽略轮毂的复杂形状**，塔筒只取最小直径 `D_tmin`、叶片只取平均宽度 `W_bavg`。原话：「通过这一简化，改进的 NMPC 算法便可在保证安全性的前提下，对风机进行最大程度的近场巡检」（印刷页 16）。
  ⇒ **这是「在线避障替代离线几何建模」的明确声明**，与 wt_inspection 的设计哲学正相反。

### 4.3 16 条路径的几何设计（§2.3.1、§2.3.3）

**塔筒 4 条**：前/后/左/右四个方向，每条与塔筒中心线保持

```
(D_tmin / 2) + d     即 0.85 + 2 = 2.85 m（离轴）
```

**叶片：每叶 4 条，共 3×4 = 12 条**（原文「本文为每个叶片分别设计了 4 条主要巡检路径」）：

| 路径 | 到叶片表面的距离 |
|---|---|
| 迎风面 / 背风面 | `d`（= 2 m，贴近叶片表面） |
| 前缘 / 后缘 | `W_bavg + d`（离**叶片中线**，以适应曲率变化） |

**「前缘或后缘始终面向风机前方」**（原文，印刷页 17）：

> 「为了进一步提高巡检精度，确保后续能够准确地确认损伤位置，本文设定巡检时风机叶片的前缘或后缘始终面向风机前方。这样设计主要是为了简化路径生成过程，使得巡检任务更加高效。」

`[?]` 这句话的语义论文没有展开。我的读法：**让被检的边（前缘或后缘）朝向风轮迎风侧**，即无人机在迎风侧方向上观察该边，使损伤位置可由「哪个面 + 沿叶片展向位置」唯一确定，从而省掉一个坐标维度、简化路径生成。**论文未给出几何定义式，也未画出示意，属于「一句话带过」的设计约束。** 不要按这句话去实现任何东西。

⚠️ **条数自相矛盾 [V]**：摘要与 §2.3.3 首段都写「共计 **12** 条主要巡检路径」，但同段给出的执行顺序是「依次跟踪 **4 条塔筒**的主要巡检路径 → **6 条**叶片前后缘 → **6 条**叶片迎背风面」= **16 条**。12 = 3 叶 × 4 条（只数叶片），16 = 12 + 4（塔筒）。**「12 条覆盖塔筒和叶片」这个摘要表述与正文的执行序列对不上。**

### 4.4 转弯处的路径点排布优化（§2.3.2，**本项目最可能借鉴的一节**）

问题陈述：塔筒 4 条轨迹的交界处（图 2-4）、每叶前后缘/迎背风面交接处（图 2-5）**转弯角度大**；路径点过于分散会使无人机出现大幅姿态调整、影响稳定飞行。

两条对策：

1. **路径端点处「轨迹点叠加设计」**：在每条主要路径的**终端处增加密集轨迹点**（图 2-4/2-5 的**绿色点** = 「主要巡检路径始终点」），使无人机**接近转弯时自然减速**，为转弯做好准备 —— 即用航点**密度**代替显式速度指令来做减速。
2. **连接路径也密集排点**：路径切换区加密，给姿态调整留出时间，避免跟踪失败。

（图 2-4 图例 [V]，p026 原图：`巡检路径` / `巡检轨迹点`（橙）/ `塔筒主要巡检路径始终点`（绿）/ `风机塔筒底部散点图`（蓝）。图 2-5 同构，蓝点改为「风机叶尖散点图」。）

### 4.5 过渡路径与「故意穿过轮毂」（§2.3.3）

- **塔筒底部**切换处：按塔筒最小半径 + 巡检距离设计**直角形式**过渡路径（图 2-4）。
- **叶片尖端**：先把路径**延伸 `d_b = 3 m`**，再连接迎风面↔背风面、前缘↔后缘（图 2-5）。
- **其余所有路径之间的转换**：

> 「由于设计完全避开风机的路径太过复杂，故采用**直接连接**的方式，如图 2-6 的红色线条显示了**穿过轮毂**的部分路径，后续由改进 NMPC 轨迹跟踪算法的避障功能自动调整风机的位置，从而避开风机部件。」（印刷页 18）

⇒ **论文明确承认自己的标称路径是穿模的，把避障责任全部推给在线控制器。** 这是本报告最重要的一条冲突点（见 §10）。

- **塔筒路径高度** `d_t = 68.8 m`（表 2-3）：由式 (2-5) 的竖直覆盖范围与塔筒高度 `H_t = 70 m` 决定，目的是「避免无人机在塔筒巡检时距离地面过近，并且不能遗漏塔筒底部区域」。70 − 68.8 = 1.2 m，`[?]` 与 `W_v/2 = 1.255 m` 接近 —— 疑为「路径高度 = H_t − W_v/2」（即让视场下缘刚好扫到塔底），但论文没有写这个式子，**属于我的反推，标注为未证实**。
- **飞进/飞出路径**：起终点各设一段专门路径，模拟「从定位到轮毂开始巡检 → 完成后驶离」的完整过程。

### 4.6 路径生成算法与验证（§2.4）

输入只需少量几何数据：**风机世界坐标、三个叶尖位置、塔筒高度、塔筒最小半径、叶尖延伸距离**。轮毂中心由三叶尖求平均得到：

```
P_hub = (P_b1 + P_b2 + P_b3) / 3        (2-6)
```

⚠️ **式 (2-6) 的物理前提是「三叶片 120° 均布且等长」**，论文未声明该前提。**且它算出的不是轮毂中心的真实位置，而是三个叶尖的形心** —— 只有在叶尖位于同一平面、等半径、理想 120° 分布时才等于轮毂中心。论文把叶尖位置当作「由计算机视觉和深度学习识别定位」的输入（印刷页 15），却**没有讨论识别误差如何传入这个平均**（对照：Su 等人的方案里这项误差是 2 m）。

仿真参数（表 2-3，PDF 页 29 原图核对）：

| 参数 | 值 |
|---|---|
| 叶片 1 尖端位置 `P_b1` | (−0.76, 24.79, 102.37) m |
| 叶片 2 尖端位置 `P_b2` | (6.39, 14.70, 34.35) m |
| 叶片 3 尖端位置 `P_b3` | (1.90, −39.50, 77.05) m |
| 巡检距离 `d` | 2 m |
| 叶尖延伸路径距离 `d_b` | 3 m |
| 塔筒主要巡检路径距离 `d_t` | 68.8 m |

⚠️ **三个叶尖不共面、不等半径 [V]（我复算）**：以三点形心为原点，
`P_b1` 相对形心 (−1.27, 21.82, 30.94)，模长 **37.86 m**；
`P_b2` 相对形心 (5.88, 11.73, −37.08)，模长 **39.33 m**；
`P_b3` 相对形心 (1.39, −42.53, 5.62)，模长 **42.91 m**。
**半径差达 5.05 m（37.86 vs 42.91），三点明显不共面。** 这说明：要么 `P_hub = 均值` 只是「路径展开起点」的一个**几何近似**（论文自己的用词是「轮毂中心点…即这三个叶片尖端点的中心点」，即它**定义**了轮毂中心 = 形心），要么这组叶尖坐标本身是随手取的示意值。**无论哪种，`(2-6)` 都不能当作「由叶尖反解轮毂」的可用公式** —— 它没有利用叶片长度/方位角约束，误差直接进路径原点。

验证方式（**注意其强度**）：SolidWorks 建三维模型 → 宏导出表面点云 → MATLAB 把点云与路径点画在同一坐标系（图 2-7、2-8），**目视检查「路径覆盖了整个风机」**。**没有任何量化指标**（覆盖率、最近距离、航段长度、转弯半径），**也没有碰撞检测**。所谓「验证了路径规划的有效性」= 看图。

## 5. 第三章：基于 EKF 的多传感器融合状态估计（PDF 页 32–49，印刷页 23–40）

> **先说结论**：这一章是**标准教科书写法**（四旋翼拉格朗日建模 + EKF 线性化推导 + 传感器误差模型 + 多源融合），**没有任何面向风机巡检场景的创新**。论文自己也在 §3.4.1 开头承认：「由于位姿估计的目的是给 NMPC 轨迹跟踪算法提供精确的实时状态量信息，因此接下来本文将重点介绍该过程所需的相关传感器」—— 即传感器选型是由**控制器需要什么状态量**倒推的，不是由巡检场景倒推的。

### 5.1 建模（§3.2）

- 机型选择：「十字型」布局（相对角同向、相邻反向旋转），理由是「简化建模过程和提高控制系统的可实现性」。
- **世界坐标系定义值得注意**：「坐标原点 `o_e` 的位置与**风机塔筒底部的圆心位置重合**，`o_e x_e` 轴指向地球正北方，`o_e y_e` 轴指向地球正东方」（印刷页 25）。⇒ **整个仿真世界是以塔底为原点的**，这对理解表 2-3 的叶尖坐标（z 高达 102 m）很重要。
- 姿态：欧拉角 Z-Y-X 序（绕 `z_e` 转 ψ → 绕中间 `y` 转 θ → 绕 `z_b` 转 φ）。⚠️ **原文这里写「绕第二个中间坐标系的 `o z` 轴旋转 φ」，OCR 与图 3-3 的 (c) 都如此 —— 按 ZYX 惯例应为绕 `x` 轴。`[?]` 疑为笔误，但式 (3-6) 的 `R_b^e` 展开式我核对过，与标准 ZYX 一致，所以结论不受影响。**
- 动力学：拉格朗日法，状态量 12 个（位置 3 + 速度 3 + 姿态角 3 + 角速度 3）。
- **五条建模假设（印刷页 27）**，其中三条对迁移判断很关键：
  - c. 推力/力矩与转速平方成正比；
  - d. **忽略空气阻力**；
  - e. **「暂时忽略风的扰动对无人机的影响」**。
  ⇒ 全文没有任何风扰动模型。**风机近场巡检恰好在风最大的地方**（叶尖速度可达 80–90 m/s，尾流湍流强烈），这个省略在论文里没有作为局限被讨论。

### 5.2 EKF 推导（§3.3）

纯标准流程：非线性系统离散模型 → 一阶泰勒展开 → 雅可比 `Φ`/`H` → 预测（式 3-30/3-31）→ 卡尔曼增益（3-32）→ 更新（3-33/3-34）。**没有任何针对本场景的改动。**

### 5.3 传感器误差模型（§3.4.1）—— **本节唯一可能对项目有用**

对每个传感器都建了「测量 = 真值 + 漂移 + 白噪声」的模型，且**漂移全部建模为高斯随机游走**（`ḃ = n_b`）：

| 传感器 | 测量模型 | 漂移建模 | 在融合中的角色 |
|---|---|---|---|
| 三轴加速度计 | `a_m = a + b_a + n_a` | `ḃ_a = n_{b_a}` | **预测**（积分得 v、p）；姿态上修正 φ、θ |
| 三轴陀螺仪 | `ω_bm = ω_b + b_ω + n_ω` | `ḃ_ω = n_{b_ω}` | **预测**（积分得姿态角） |
| 三轴磁力计 | `m_m = m + b_m + n_m` | `ḃ_m = n_{b_m}` | **修正** ψ（航向） |
| GPS | `p_GPS = p + b_p + n_p`，`v_GPS = v + b_v + n_v` | `ḃ_p = n_{b_p}`, `ḃ_v = n_{b_v}` | **修正**水平位置/速度 |
| 气压计 | `d_baro = h_s − Δh + b_dbaro + n_dbaro` | `ḃ_dbaro = n_{b_dbaro}` | **修正** z 向位置（微分后修 v_z） |

- 气压计高度换算：`h_s = 44330·[1 − (P/P_0)^(1/5.255)]`（式 3-50，P_0 = 101.325 kPa），再减基准海平面差 `Δh`（式 3-51）。
- 磁偏角补偿：**「北京磁偏角约为 6° 偏西」**（印刷页 36）—— 这是论文里唯一一个带地理位置的具体数字。
- **偏航角由磁力计算**：`ψ = −arctan(m_by / m_bx)`（式 3-45，p046 原图核对）。
- 加速度计反算姿态：`θ̂_m = −arcsin(a_bmx/g)`，`φ̂_m = arctan(a_bmy/a_bmz)`（式 3-39，p044 原图核对）。

### 5.4 融合结构（§3.4.2 / §3.4.3）

```
位置/速度：  加速度计 ──积分──▶ v, p ──修正──▶ GPS(水平) + 气压计(垂直)
姿态：       陀螺仪  ──积分──▶ 四元数 q ──修正──▶ 加速度计(φ,θ) + 磁力计(ψ)
```

- **两个滤波器分开设计**，不是一个大 EKF。状态量含**传感器偏置**（`b_a, b_p, b_v, b_dbaro` / `b_ω, b_m`），即偏置在线可观测估计。
- 姿态用**四元数**做状态量，转欧拉角后交给 NMPC。四元数→欧拉角（式 3-54）：

```
φ = arctan[ 2(q_0q_1 + q_2q_3) / (1 − 2(q_1² + q_2²)) ]
θ = arcsin[ 2(q_0q_2 − q_3q_1) ]
ψ = arctan[ 2(q_0q_3 + q_1q_2) / (1 − 2(q_2² + q_3²)) ]
```

（这是标准公式，我核对无误 `[V]`。）

### 5.5 ⚠️ 这一章最大的方法论问题：**没有真值**

「融合结果既为相机对准控制器提供了精准的位置信息，还为 NMPC 控制器提供了可靠的状态输入。**对比实验表明，相较单传感器，EKF 在无人机位置、速度及姿态估计方面均展现出更高的稳定性和精确性**」（摘要）。

但第五章说传感器仿真数据是**「基于 NMPC 仿真数据，建立多传感器误差模型，生成传感器仿真数据」**（摘要）—— 也就是说：

> **「真值」= NMPC 自己跑出来的理想轨迹 → 按论文自建的误差模型加噪 → 再由 EKF 滤回来 → 与「真值」比较。**

**误差模型和滤波器由同一个作者、基于同一套假设设计**，这是典型的 self-consistency 验证，不是外部验证。它能说明「EKF 实现没写错」，**不能说明「在真实风场中精度够用」**。论文对此没有讨论。⇒ 见 §11 存疑项。

**与 wt_inspection 的关系**：项目当前**不做状态估计** —— 位姿直接来自 PSDK 的 `dji_fc_subscription` 话题（飞机自己融合好的），机载端只做相位反解与滤波/外推。**A 篇这一章整体不可迁移**，唯一有价值的是**「哪些量需要外部修正」的清单**（GPS 高度不可靠、磁力计需磁偏角补偿、加速度计积分漂移），可用来判断 PSDK 话题值的可信区间。

## 6. 第四章：基于改进 NMPC 的轨迹跟踪（PDF 页 50–61，印刷页 41–52）

### 6.1 状态空间模型（§4.2.2）

```
x = [P_x, P_y, P_z, v_x, v_y, v_z, φ, θ, ψ, p, q, r]^T     (4-5)
u = [Ω₁², Ω₂², Ω₃², Ω₄²]^T   —— 四个旋翼转速的平方     (4-6)
ẋ = f(x, u)
```

直接用第三章拉格朗日模型的 (3-14)(3-18) 代入。**实现手段**：MATLAB 符号运算工具箱定义状态/控制/参数 → 化简状态方程 → **`matlabFunction` 生成可执行代码**（印刷页 42）。⇒ 这是「符号推导 + 代码生成」路线，**不可迁移到 C/PSDK**。

### 6.2 两个创新项（§4.3，**本章的核心**）

#### (a) 避障项 `J_obs`（式 4-8，p054 原图逐字核对）

```
J_obs = Σ_{k=0}^{N-1}  Q_obs · ‖v_{t+k}‖² / (d_k² + ε) · 1_{ d_k < d_threshold }        (4-8)
```

| 符号 | 含义 | 论文原话要点 |
|---|---|---|
| `d_k` | 无人机当前位置与障碍物（叶片/塔筒/轮毂）的**最小距离** | 「利用 **KD-Tree** 数据结构高效查询局部风机点云数据」，动态实时计算 |
| `d_threshold` | 安全距离阈值 | 「当 `d_k < d_threshold` 时，算法会激活障碍代价项」。**「安全距离阈值并不等同于理论上 2 米的最小安全距离，其原因和具体取值将在第五章结合仿真实验详细讨论」** |
| `Q_obs` | 权重系数 | 调大 → 更保守 |
| `v_{t+k}` | 预测时域内的速度向量 | 「将三个方向的速度平方和纳入计算」 |
| `ε` | 小正数 | 防分母为零 |

三个设计要点（论文自述）：
1. **`d_k` 放分母** → 避障代价与距离成反比，接近障碍物时代价显著增大。
2. **乘速度平方** → 「当无人机以较高速度接近障碍物时 `J_obs` 显著增大，促使无人机提前减速或调整航向」。
3. **指示函数门控** → 只有进入 `d_threshold` 才计代价。

⚠️ **「2 米安全距离」的真实地位 [V]**：摘要声称「与风机始终保持 2 米的安全距离」，但正文明确区分了两件事 —— **`d = 2 m` 是第二章的路径设计距离**，**`d_threshold` 是 NMPC 里另一个待调参数**，且论文自己说两者不等同。⇒ **「2 米」是设计意图，不是仿真验证出来的最小距离保证。** 第五章的最小距离分析才是判据（见 §7）。

⚠️ **`J_obs` 的数学性质值得警惕**：代价里**只有斥力项，没有「远离后的奖励」**，且指示函数在 `d = d_threshold` 处**不连续**（代价从 `Q_obs‖v‖²/(d_th²+ε)` 直接跳变到 0）。这会给梯度型求解器（`fmincon`/`quadprog`）带来非光滑性。论文**没有讨论这个不连续性**，也没有给出 `d_threshold` 的取值。

#### (b) 控制输入变化量惩罚项 `J_u`（式 4-9，p053 原图核对）

```
J_u = Σ_{i=0}^{M-1} ‖Δu_{t+i}‖²_S ,    Δu_{t+k} = u_{t+k} − u_{t+k−1}      (4-9)
```

论文给的三条理由：平滑飞行轨迹（**「平滑的飞行轨迹不仅能够提高巡检图像的清晰度」**）、降低执行器负载、提升系统稳定性。

> **这一条与 wt_inspection 有一条直接对应**：项目里 `bladeSpacingM`/航点间距决定了云台与机身的角速度，而 M4T 走 KMZ 航点时**飞控自己会做加减速**，项目只能通过**航点密度**间接影响（这与 A 篇 §2.3.2 的「端点密集排点」是同一个手法）。见 §9。

### 6.3 完整优化问题（式 4-10，p053 原图逐字核对）

```
        min
u(t), u(t+1), …, u(t+M−1)   J = Σ_{k=0}^{N−1} ( ‖x(t+k+1) − x_ref(t+k+1)‖²_Q + ‖u(t+k)‖²_R )
                                  + Σ_{i=0}^{M−1} ‖Δu_{t+i}‖²_S
                                  + Σ_{k=0}^{N−1} Q_obs · ‖v_{t+k}‖²/(d_k² + ε) · 1_{d_k<d_threshold}

        s.t.   ẋ = f(x, u),                k = 0, …, N−1
               x_min ≤ x ≤ x_max,          k = 0, …, N
               u_min ≤ u ≤ u_max,          k = 0, …, M−1
               u_{t+k} = u_{t+M−1},        k = M, …, N−1
               Δu_{t+k} = u_{t+k} − u_{t+k−1},   k = 1, …, M−1
```

即：**传统 NMPC（跟踪 + 控制量惩罚） + `J_u` + `J_obs`**。约束是箱式约束 + 控制量在 `M` 之后保持不变（控制时域 `M` < 预测时域 `N`）。**没有终端约束、没有终端代价、没有递归可行性/稳定性证明。**

### 6.4 相机对准机制（§4.4）—— **四篇里唯一有「对目标点定向」内容的章节**

**四分区 + 四条中心线**（图 4-2/4-3，p56）：把风机分成 4 个区域 —— **3 条叶片中心线**（各从轮毂中心 `P_hub` 延伸到对应叶尖）+ **1 条塔筒中心线**。

**目标点选择流程**（§4.4.1）：

```
NMPC 避障时算出的「风机与无人机距离最近的位置点」 → 判定它属于哪个区域
  → 选对应的中心线 → 把无人机位置垂直投影到该中心线 → 投影点 = 相机对准目标点
```

投影计算（式 4-11/4-12，p57）：

```
d_c = P_end − P_start
P_proj = P_start + [ (C − P_start)·d_c / ‖d_c‖² ] · d_c
```
并**夹到线段两端**（超出起点取起点、超出终点取终点）。

**云台角计算**（§4.4.3，式 4-13/4-14/4-15，p58–59）：

```
P_c^b = R_b^eᵀ (P_proj − P_uav)        把目标点转到机体坐标系   (4-13)
ψ_c = arctan( (x_c^b − x_yawb) / (y_c^b − y_yawb) )              (4-14)
θ_c = arctan( −(z_c^b − z_pitchb) / √( (x_c^b − x_pitchb)² + (y_c^b − y_pitchb)² ) )   (4-15)
```
即 **yaw 转轴与 pitch 转轴分别有自己的位置**（不与质心重合），故两个角各自以其转轴为原点算。

⚠️ **一个被作者显式承认的简化**（印刷页 49）：

> 「由于无人机在主要巡检路径上飞行时，其三个欧拉角变化极小，且它们的值保持在 0 附近，因此**可以忽略无人机姿态对相机云台控制的影响**。」

`[?]` 但式 (4-13) 里**仍然用了 `R_b^e`** —— 与这句话自相矛盾（若真可忽略，就该直接用世界系差值）。**这两处至少有一处是笔误或表述不严。** 而且「三个欧拉角保持在 0 附近」对一个**绕塔筒做直角转弯**（§2.3.3）的航线是可疑的假设。

⚠️ **「对哪一点成像」这件事，A 篇与 wt_inspection 的根本分歧**（见 §10）：A 篇瞄的是**叶片中心线上的投影点**（即「无人机离风机最近处的中心线垂足」），而 wt_inspection 的几何俯仰公式瞄的是**杆顶/目标点**（`lz` 项目是杆顶，`wt` 项目是叶片站位）。**A 篇这个「投影点」随无人机位置连续滑动，与「叶片上的固定物理点」不是一回事** —— 它保证的是「镜头看向最近区域的轴线」，而不是「镜头锁定某个损伤位置」。论文称其解决「损伤位置确认」问题（§2.3.1 提到「确保后续能够准确地确认损伤位置」），但这个机制本身**不提供目标点的绝对位置**，只提供视线方向。

### 6.5 系统集成（§4.5）

```
路径规划与生成 → 巡检轨迹 ──┐
                            ├─▶ NMPC 控制器 ──▶ 无人机
风机表面点云 ───────────────┘        │
                                     │「当前时刻风机与无人机距离最近的位置点」
                                     ▼
EKF(位置/速度/姿态) ──────▶ 相机对准控制器 ──▶ 云台 yaw/pitch
```

**关键耦合**：**NMPC 的避障计算副产品（最近点）被复用为相机对准的输入。** 这是本章唯一的「一鱼两吃」设计，但代价是：**避障与对焦被绑死，避障一失效（`d_k > d_threshold` 时 `J_obs` 门控关闭），最近点仍要算**（论文没说明门控关闭时 `d_k` 是否还在算）。

## 7. 第五章：仿真分析（PDF 页 62–77，印刷页 53–68）

**平台**：MATLAB（§4.2.2 明说用符号工具箱 + `matlabFunction` 生成状态方程代码）。**没有说明求解器**（`fmincon` / `quadprog` / 自写 SQP 均未提及），也没有报任何**单步求解耗时**。`[?]`

**场景**：世界系原点在塔底圆心（§3.2.2），风机点云来自 SolidWorks。**全程无实物、无真实传感器、无真实图像。**

### 7.1 EKF 仿真（§5.2）—— **真值是自造的**

仿真方法（§5.2 开头，印刷页 53）**值得逐字读**：

> 「本文基于 **NMPC 仿真中无人机实际运行的路径状态**，分别选取了不同时间段的飞行数据作为基准……为了真实地模拟无人机在风机近场巡检场景中的传感器测量数据，本研究在基准数据基础上，依据**中等工业级传感器的性能特性**，分别生成了 GPS、加速度计、气压计、陀螺仪和磁力计的仿真数据。」

⇒ **真值 = NMPC 理想轨迹；传感器数据 = 真值 + 论文自建误差模型；滤波器 = 论文自己设计的 EKF。三者同源。** 这是 self-consistency 验证。

⚠️ 更麻烦的是**时间段是挑过的**（印刷页 53）：

> 「之所以选择不同时间段的数据，是因为……例如，在对 x 轴方向的位置进行估计时，最好选取无人机在 **x 轴方向位置点分布较分散**的时间区域……因此，通过选择合适的时间段，能够更好地展示传感器融合算法的性能。」

⇒ **论文自己承认按「展示效果最好」挑数据段。** 这使得 RMSE 数字不可作为独立性能证据。

**噪声参数（表 5-1，p063 原图核对）**：加速度计测量噪声 σ=0.05 m/s²、零偏游走 0.002 m/s/√Hz；陀螺仪 0.01 rad/s、0.003 rad/s/√Hz；磁力计 0.05 mT、0.01 mT/√Hz；**GPS 位置噪声 σ=1.0 m、速度噪声 σ=0.15 m/s**、位置零偏 0.01 m/√Hz、速度零偏 0.001 m/s/√Hz；气压计 0.3 m、0.03 m/√Hz。

**位置/速度结果（表 5-2，Q=diag(1e-6, 1e-4)、R=diag(0.5, 0.5)，式 5-1）**：

| 状态 | 加速度计积分 | GPS 测量 | EKF 融合 |
|---|---|---|---|
| 位置 RMSE | 36.53 m | 1.02 m | **0.23 m** |
| 速度 RMSE | 1.67 m/s | 0.12 m/s | **0.04 m/s** |

- 「相比加速度计积分降低了 98.37%，相比 GPS 降低了 77.45%」/「97.60% / 66.67%」。
- **基线是稻草人**：「加速度计积分 36.53 m」是 30 s 自由二重积分的必然结果，任何实际系统都不会这么做。**EKF 相对 GPS 的 4.4× 提升才是真实信息**，但那主要来自「Q 极小 → 重观测平滑」的代价是**相位滞后**，论文在 §5.2.1.2 也承认了这个 trade-off（「过度怀疑测量数据」「可能无法及时纠正」）。
- 全局值（印刷页 59）：x/y 位置 RMSE **0.23 / 0.24 m**，x/y 速度均 **0.04 m/s**。

#### 「2 米安全距离」的核实（★ 任务点名要核实的数字）

论文的原始主张分三层，必须分开：

1. **路径设计距离 `d = 2 m`**（§2.2，印刷页 15）—— 由式 (2-3) 的 `d_min = 1.68 m` 加安全裕度得到。**这是路径标称值。**
2. **`d_threshold = 2.2 m`**（表 5-4）—— NMPC 避障项的激活阈值。论文明确说「安全距离阈值**并不等同于**理论上 2 米的最小安全距离」（印刷页 44）。
3. **实测最小距离**（§5.3.2，图 5-11 + 表 5-5/5-6）。

**图 5-11（p073 原图）**：横轴「仿真步数」0–100（**不是时间**），纵轴「最小距离 (m)」0–10。曲线在 ~3–10 m 处有两个尖峰（**飞进/飞出段**），中间段贴在 2–3.5 m。分段着色：黑=最小距离、红=巡检塔筒、蓝=巡检叶片前后缘、黄=巡检叶片迎风背风面。

论文的文字结论：

| 阶段 | `d_min` |
|---|---|
| 巡检塔筒、叶片迎风背风面 | **2 ~ 2.3 m**（形状规则、路径规整） |
| 巡检叶片前后缘 | **2.2 ~ 2.4 m**（前后缘呈不规则曲线，路径采用较近距离设计，「涉及较多避障操作，导致 `d_min` 的数值抖动更加明显且较大」） |

> 「尽管如此，整个巡检过程中，`d_min` **始终未小于安全距离 2 米**……显著优于传统无人机巡检的 10 米距离要求。」（印刷页 64）

**核实结论**：**「与风机始终保持 2 米的安全距离」这句摘要话，成立的前提是 `d_threshold` 被调到 2.2 m（即比目标多留 0.2 m）。** 这不是冗余的修辞 —— 见下表。

#### ★ 表 5-6：安全阈值 vs 实际最小距离（p075 原图逐字核对）—— **本节最有价值的一张表**

| `d_threshold` (m) | 实际 `d_min` (m) | 实际 − 阈值 |
|---|---|---|
| 2.0 | **1.65** | **−0.35** |
| 2.1 | 1.78 | −0.32 |
| 2.2 | 2.06 | −0.14 |
| 2.3 | 2.20 | −0.10 |
| 2.4 | 2.53 | **+0.13** |

论文对这一现象的**解释（原话，印刷页 66）**：

> 「虽然设定的安全距离是 2 米，但当安全阈值也设为 2.0 米时，无人机与风机的最小距离为 **1.65 米**。这是因为无人机遇到障碍时，需要进行**速度缓冲和姿态调整，这些调整需要一定的时间**，因此在收到避障信号并开始减速时，无人机与风机的距离已经小于安全阈值。」

⇒ **把安全阈值设成目标安全距离，得到的是更小的实际距离。** 缺口随阈值增大而收窄（−0.35 → +0.13，约在 2.35 m 处过零），且**斜率 > 1**（阈值 +0.4 → 实际 +0.88）—— 因为阈值越大，避障项介入越早，减速越从容。**这是一条可以直接搬到 wt_inspection 的定量教训**（见 §9.1）。

论文对 `Q_obs = 4` 的解释**很重要**（原话，印刷页 65）：

> 「当避障权重为 4 时，无人机与风机的最小距离为 **0 米**，这是因为**在路径规划中，为了简化算法设计，部分路径点位于风机内部**，导致无人机过于接近风机，表明此时避障项的影响较小，无法有效避免碰撞风险。」

⇒ **`d_min = 0` 意味着无人机穿过了风机点云。** 这是第二章「标称路径穿模、避障靠在线控制器兜底」这条设计的**直接后果**，论文自己把它当作 `Q_obs` 太小的证据，而不是当作**路径设计缺陷**。`Q_obs = 11` 时「仿真失败」—— 避障项压过跟踪项，**不收敛**。

⚠️ **最优点的选定理由不成立**：论文说「当避障权重为 8 时，最小距离达到 2.06 米，此时达到最优控制。即满足了安全距离需求，同时兼顾了近场巡检的要求」。但 **2.06 m 与路径设计距离 2 m 只差 6 cm**，而 `Q_obs = 9`（2.62 m）或 `10`（3.11 m）在「安全」这个维度上严格更优，代价只是「可能影响近场巡检的效果」——**论文没有给出任何 GSD / 清晰度数字来支撑这个代价**，所以「8 最优」实际是**主观选定**。

⚠️ **「STD 先降后升」的非单调性与论文的解释不自洽**：论文把 `S` 增大同时解释为「更平稳」（1.4→1.7）和「姿态调整变得不够平稳」（1.6→1.9）。**同一个机制（惩罚控制增量）在 1.6→1.7 是有利的、在 1.7→1.9 是有害的**，转折点恰好落在选定值 1.6/1.7 附近 —— 这正是「按最优点反推解释」的形状。且 `S=1.6` 与 `S=1.7` 的 STD 相同（0.24/0.24 vs 0.26/0.27），**最优点的分辨力在噪声量级**。`[?]`

## 8. 第六章：总结与局限（PDF 页 78–79，印刷页 69–70）

### 8.1 自述的五条贡献

与摘要一致：(1) 一体化路径规划 + 生成算法（**「仅需输入风机的几个关键参数，即可自动生成适用于各种类型风机的巡检路径」**）；(2) 多传感器融合 EKF；(3) 改进 NMPC（避障项 + 控制增量惩罚项）；(4) 相机对准控制器；(5) 仿真验证与参数优化。

⚠️ 第 (1) 条的「适用于各种类型风机」**未被验证** —— 全文只跑了一台风机（39.22 m 叶片 / 70 m 塔高）的一套参数。

### 8.2 自述的三条局限（§6.2，印刷页 70）—— **这是全书最诚实的一段**

1. **引入动态权重调整机制**：承认「控制输入变化量的惩罚项被设计为**固定权重**，虽然能平滑无人机的运动轨迹，但在复杂环境中可能无法灵活应对突发情况」。
2. **基于深度学习的风机轮毂定位**：原话 —— **「目前，本文对风机轮毂的定位是假设已知的，这在实际应用中可能存在一定的局限性。」** ⇒ **轮毂位置 = 给定常数，不是测量出来的。** 这与 §2.3 开头「首先需要利用计算机视觉和深度学习等技术，对叶片尖端的三个点在世界坐标系下的位置进行识别和定位」**直接矛盾** —— §2.3 说叶尖位置靠视觉识别，§6.2 说轮毂定位「假设已知」。**两处不能同时为真。**
3. **实物平台上的实验验证与优化**：原话 —— 「本文的研究目前主要基于仿真环境……未来的研究可以在实物平台上进行实验验证」。

### 8.3 **作者没有列为局限的局限（本报告的判断）**

- **风轮始终静止**：全文没有一处讨论风轮转动。叶尖坐标是常数（表 2-3）、障碍物是静态点云（图 5-10 的「风机云图」）、「最小距离」是到静态点云的距离。**「巡检时风机处于停机状态」是隐含前提，从未被声明。**
- **风的扰动被显式忽略**（§3.2.3 假设 e），且第五章没有任何风扰仿真。
- **路径穿模**（§2.3.3）在第六章**没有被提及**，反而在 §5.3.3.1 里作为「`Q_obs` 太小的证据」被轻描淡写地带过。
- **EKF 与 NMPC 未接通**（§5.3.1 自述）在第六章**没有被列为局限**。
- **无实物、无图像、无检测**：标题与摘要反复出现「巡检图像的质量和有效性」「损伤定位」，但**全文没有一张真实图像、没有任何检测算法、没有 GSD 数字**。「提升图像质量」的论据只有「平滑的飞行轨迹能够提高巡检图像的清晰度」（§4.3.2）这句断言。
- **无计算耗时**：`N=24, M=8` 的 NMPC 每步求解耗时、EKF 每步耗时、路径生成算法耗时**全部未报**。论文称路径生成算法「计算量低」，但**没有任何复杂度分析或计时**。

## 9. ★ 可迁移到 wt_inspection 的条目

> 本节逐条对照同批 B/C/D/E 四篇报告的第 6 节，**只写 A 篇独有或与它们不同的**；重复的（相位反解视觉路线、覆盖率核验、入射角约束、解析判交）在末尾 §9.8 一句话带过。

### 9.1 【最高价值】安全裕度必须从**动力学**反推，不能设成目标值 —— 表 5-6 的定量教训

- **论文做法**（§5.3.3.2，表 5-6，印刷页 66）：把 NMPC 的避障激活阈值 `d_threshold` 直接设成目标安全距离 2.0 m 时，**实际最小距离只有 1.65 m**（差 −0.35 m）。原因是「无人机遇到障碍时，需要进行**速度缓冲和姿态调整，这些调整需要一定的时间**，因此在收到避障信号并开始减速时，无人机与风机的距离已经小于安全阈值」。补上 0.2 m 裕度（`d_threshold` = 2.2 m）后实际 `d_min` = 2.06 m。完整映射（阈值 → 实际）：2.0→1.65、2.1→1.78、2.2→2.06、2.3→2.20、2.4→2.53，**缺口随阈值单调收窄，约在 2.35 m 处过零**。
- **wt_inspection 现状**（读码 `[V]`）：`minSafeDistM`（`wt_plan.h:52`，默认 3.0 m）是**直接**与几何距离比较的硬下限 —— `wt_test_plan.c:182` 断言 `rep.minSafeDistM` 落在 7.0~7.5 m。**没有任何速度相关的裕度**，判据是「站位到叶片轴线的静态距离 > 3 m」。
- **差异（关键）**：**A 篇的 `d_threshold` 是「开始刹车的距离」，`minSafeDistM` 是「允许的最小距离」—— 两个物理量，不能互相赋值。** 论文实测的「刹车距离缺口」在 0.1~0.35 m 量级。wt_inspection 的飞行速度更低（航点速度由 `wt_bridge` 下发），但**风场中叶尖的动态摆幅**（README 已知限制：「未考虑风速下叶尖的动态摆幅，转动模式下 `min_safe_dist` 需按现场风速调大」）会叠加进来。
- **具体动作**：把 `minSafeDistM` 的语义在文档里明确成「**几何**安全距离」，另设一个 `dynamicMarginM`（或直接规定 `minSafeDistM` 必须 ≥ 几何安全距离 + 裕度），裕度来源按 `v · t_响应 + 叶尖摆幅` 估。**至少要在 README 的「已知限制」里把「3.0 m 是静态判据，不含刹车距离与动态摆幅」写清楚** —— 现在这条只对「转动模式」提了，静叶模式没有。
- **代价与风险**：低（文档 + 一个配置项）。风险是把两套数字混用 —— 论文的 0.35 m 是**自研四旋翼 + 自建模型**的仿真值，**不能直接抄**；要抄的是「必须留裕度」这个判据和「阈值设成目标值会欠账」这个形状。

### 9.2 【高价值】航点转弯的稳定性 —— A 篇的「密集排点」只是半个答案，另一半在 wpml 里

- **论文做法**（§2.3.2，印刷页 17）：在**每条主要路径的终端**和**路径连接段**「密集设置轨迹点」，理由是「使无人机在接近转弯时**减缓飞行速度**，为转弯做好准备，从而避免大幅度的姿态调整」。图 2-4/2-5 里这些点被画成**绿色**（图例：「塔筒主要巡检路径始终点」/「叶片主要巡检路径始终点」）。
- **论文的局限**：**它只能靠航点密度间接减速**（自研控制器，航点是采样点）。而且论文**没有量化「密到什么程度」** —— 没说相邻点间距、没有转弯半径数字。
- **wt_inspection / liangzhourenwu 现状**：`wt_bridge.c:410` 写的是 `waypointTurnMode = toPointAndStopWithDiscontinuityCurvature` + `waypointTurnDampingDist = 0` + `useStraightLine = 1` —— 即**到点停、走直线**。`liangzhourenwu/lz/doc/WPML-ORBIT.md` 已经把这个语义彻底查清并量化了 `[V]`：`useStraightLine=1` 是**内接正多边形**，`useStraightLine=0` + `toPointAndPassWithContinuityCurvature` 才是弧线；**半径 20 m / 8 点，直线模式实际离杆 18.48 m（−7.6%），弧线模式近似圆**。
- **差异**：A 篇解决「转弯时姿态抖动」，走的是**采样密度**这条路；wt_inspection 手里有**更直接的两个旋钮**（`waypointTurnMode` 与 `waypointTurnDampingDist`），而且 lz 项目已经验证过后者。**A 篇的价值在于给出了「为什么必须在转弯处减速」的物理理由（速度缓冲需要时间），这正是 wt_inspection 目前用 `toPointAndStop` 硬性解决的同一件事** —— 到点停本身就是"速度缓冲"的极端形式。
- **具体动作**：无需改代码。**在 wt_inspection 里补一段「为什么航点用 toPointAndStop」的说明**（现在 `wt_bridge.c` 只写了常量，没写理由），并把 A 篇的论证引为外部依据；同时提醒：**若要改弧线模式，必须同时处理 §9.1 的裕度问题**（弧线会切内角，实际离障碍更近 —— 这正是 lz 项目量化的 −7.6%）。
- **代价与风险**：零（文档）。风险是照抄 A 篇的「堆密航点」—— 对 KMZ 路线，航点密度不是减速手段，是**站位密度**（会改变拍照位置），混用会破坏重叠率。

### 9.3 【中高价值】「最近点 → 分区 → 中心线投影」的相机对准机制 —— 一个**不需要目标检测**的指向方案

- **论文做法**（§4.4，印刷页 46–49）：把风机划成 **4 个区域**（3 叶片 + 1 塔筒），每个区域一条中心线；由避障算出的「最近点」判定区域 → 选中心线 → 把无人机位置**垂直投影**到该中心线（式 4-12，并夹到线段两端）→ 投影点即相机目标点 → 由云台 yaw/pitch 转轴位置分别反算两个角（式 4-13~4-15）。
- **wt_inspection 现状**：相机俯仰/朝向**没有显式模型**。KMZ 侧靠 `waypointHeadingMode=followWayline`（机头跟航线）+ `waypointPoiPoint`（`wt_bridge.c:403`，当前写死 `0,0,0`）。`lz` 项目（同一套 PSDK 栈）已经用 `towardPOI` + 机头对准圆心的方案，并在真机上验证过「机头始终对圆心」`[V]`。
- **差异**：A 篇的机制**完全不需要图像、不需要目标检测、不需要云台角反馈** —— 纯几何，输入只有无人机位置和一条中心线。**这对"项目目前没有任何图像获取能力"这一硬约束是友好的**：它是唯一一条不依赖视觉就能"让相机看向正确位置"的路线。
- **具体动作**：把 `wt_bridge.c` 的 `waypointPoiPoint` 从 `0,0,0` 改成**按航段计算的实际目标点**（叶片段取该段对应的叶片轴线上的垂足，塔筒段取塔筒轴线上的垂足 —— 与 A 篇式 4-12 同构），并让 `waypointHeadingMode` 从 `followWayline` 改为 `towardPOI`。**这是纯几何，可进 `wt_core` 回归测试**（给定站位与叶片轴线，断言 POI 点落在轴线上、且投影点被夹到轴段内）。
- **代价与风险**：中。`towardPOI` 在 lz 项目已验证但**wt_inspection 未验证**；且 A 篇的「中心线」是**简化直线**（塔筒中心线「高度与 `P_hub` 一致」），与 wt_inspection 的解析塔筒（锥度）不完全一致 —— 塔筒段用轴线即可，叶片段要注意叶片的**预弯（prebend）与锥角**，投影到直线中心线会有偏差。
- **与 B/C/D/E 的关系**：B 篇 6.3 讲「面片级可巡检性校验」（**验证**拍到了），C 篇 6.5 讲轮毂检测对准初始作业点（**视觉伺服**），E 篇 6.1 讲取证照片反解相位（**视觉反解**）。**A 篇这条是唯一「不引入视觉就能改善指向」的**，与它们互补而非重复。

### 9.4 【中价值】用「视场覆盖宽度」反推最近站位距离 —— 与 `wt_camera` 同一件事的两个方向

- **论文做法**（§2.2，式 2-3）：`d_min = W_bmax / (2·min[tan(HFOV/2), tan(VFOV/2), tan(DFOV/2)])` —— 给定**被摄物宽度**与**视场角**，求能装下它的**最小距离**。得到 1.68 m，加裕度取 2 m。再反算覆盖 `W_h = 2d·tan(HFOV/2) = 3.35 m`、`W_v = 2.51 m`。
- **wt_inspection 现状**（读码 `[V]`）：`wt_camera.h` 有 `WtCamera_MaxDistanceForGsd()`（GSD → 最大距离）、`WtCamera_CoverageHeightAt/WidthAt()`（距离 → 覆盖尺寸）、`WtCamera_SpacingForOverlap()`。**方向齐全。**
- **差异 —— 一个真实的功能缺口 `[V]`**：`WtCamera_CoverageHeightAt` 只被 `wt_plan.c:357` 用来填报告的 `coverageM` 字段；**`WtCamera_CoverageWidthAt` 在整个 src 里没有任何调用者**（只在 `wt_camera.c` 内部被 `SpacingForOverlap`/`OverlapForSpacing` 用）。也就是说：**项目算了「画面能覆盖多宽」，但没有用它校验「这个宽度装得下叶片弦长吗」。**
- **具体动作**：在 `wt_plan` 的站位生成里加一条**与 A 篇式 2-3 同构的校验** —— 每个站位处 `CoverageWidthAt(standoff) ≥ 叶片局部弦长`（叶片弦长在 `wt_turbine` 的解析几何里已有），不满足则告警或自动拉远。这比只查 GSD 更直接：**GSD 保证「看得清」，覆盖宽度保证「看得全」**。
- **代价与风险**：低，纯几何、可桌面测试。风险：叶片弦长沿展向变化大（叶根到叶尖），要用**局部弦长**而非最大弦长，否则叶尖处会过度拉远。

### 9.5 【中价值】"指定靶点画幅比例"是一个显式的、可核算的约束

- **论文做法**：式 (2-3) 取三个半视场角的 **min** —— 即要求 `W_bmax` 在**三个方向上都装得下**（保守取最窄的那个）。这是「指定靶点占满画幅」的显式形式化。
- **wt_inspection 现状**：`targetGsdMmPerPx`（目标 GSD）是**分辨率**约束，站位距离由它反算（`WtPlan_ResolveStandoff`，`wt_plan.c:266`）。**没有任何「目标在画面中应占多大」的约束** —— 相机可能把叶片拍成画面中央的一条细线（尤其长焦 168 mm，`wt_camera.h` 的例子：FOV_diag 只有 14.68°）。
- **差异**：GSD 决定「细节可辨」，画幅占比决定「目标在画面里够大、够居中（畸变小）」。**E 篇 6.2 已经从「多视角交会」角度提过站位几何，E 篇结论 5 还提到「关键点应位于画面中心区域」；A 篇式 2-3 提供了这条约束的闭式形式。**
- **具体动作**：与 §9.4 合并做 —— 在站位校验里同时报告「画面覆盖宽度 / 局部弦长」这个比值，作为**可观测的诊断量**（不一定要做成硬约束）。当前 `wt_plan_demo` 的「相机模型核验表」正适合加这一列。
- **代价与风险**：低。

### 9.6 【中价值】给「危险航段修补」的判据找一个**外部定量锚点**

- **论文做法**：`d_min` 在**飞进/飞出段**会冲到 3~10 m（图 5-11 的两个尖峰），在巡检段压到 2~2.4 m。这给出一个形状：**「进出场距离远、作业段距离近」是正常剖面**，而「作业段出现尖峰」说明绕远了。
- **wt_inspection 现状**：`wt_plan.c` 的六类危险航段修补（README「安全设计要点」）是**离散采样判交 + 出壳→沿弧→换高**，但没有一个「修补后的剖面长什么样算正常」的参考形状。
- **差异**：A 篇给了「距离随仿真步数的剖面」这一诊断视图（图 5-11），wt_inspection 的报告里**没有这条曲线**（只有 `minSafeDistM` 一个标量 + 违规计数）。
- **具体动作**：`wt_plan_demo` 输出一条**逐航点的「到最近障碍距离」序列**（纯几何，`wt_core` 可算），让「修补前后」和「不同配置之间」可比。**判据进 `wt_core` 测试**：修补后的剖面不得出现新的低谷。
- **代价与风险**：低。风险是输出太啰嗦（航点多时），按航段聚合即可。

### 9.7 【低-中价值】路径生成算法的输入清单 —— 一张可对照的「最小台账」

- **论文做法**（§2.4，印刷页 19）：算法只需 **5 类输入** —— 风机世界坐标、三个叶尖位置、塔筒高度、塔筒最小半径、叶尖延伸距离。参数表（表 2-3）只有 6 行。
- **wt_inspection 现状**：`WtTurbineSpec`（`wt_turbine.h`）有 hubHeight / rotorDiameter / coneAngleDeg / tiltDeg / headingDeg / prebendM 等**台账参数**，比 A 篇丰富得多（A 篇只取最小直径和平均宽度，因为避障交给在线控制器）。
- **差异**：A 篇的「少参数」不是优点，是**把复杂度推给了在线避障**（§4.3.1 明说「为了简化路径规划的复杂度……在设计的参考路径会有穿过风机轮毂的情况」）。**wt_inspection 的「参数多」换来了离线可验证性** —— 这正是 A 篇缺的。
- **具体动作**：无需迁移。**建议在 wt_inspection 的文档里明确写下这条权衡**：台账参数多不是负担，是「安全判据能落在离线」的代价；凡是能把参数从「在线估计」搬到「台账配置」的，都应该搬。
- **代价与风险**：无。

## 10. 冲突点

### 10.1 安全责任的位置：在线 vs 离线（**根本分歧**）

| | A 篇 | wt_inspection |
|---|---|---|
| 标称路径 | **明确承认穿模**（「部分路径点位于风机内部」，印刷页 65；图 2-6 红线穿过轮毂） | 航线生成后**统一扫描全部航段并修补**，落盘前拒收 |
| 安全由谁保证 | NMPC 的 `J_obs` 项，**靠仿真调参**（`Q_obs`、`d_threshold`） | 解析安全校验 + 危险航段修补，**离线可复算** |
| 失效模式 | `Q_obs = 4` → `d_min = 0 m`（穿过风机）；`Q_obs = 11` → 不收敛 | 违规计数 > 0 → 拒绝出图 |
| 可测试性 | 无（MATLAB 跑一遍看图） | `ctest` 回归 |

**这不是「谁更好」的问题，是「执行体不同」的必然结果**：A 篇控制轨迹，可以在线修正；wt_inspection 走 KMZ 预下发航点，**机载应用不控轨迹，飞机不会因为「快撞了」而绕开**。⇒ **A 篇的「路径可以穿模、避障兜底」这条路线，对 wt_inspection 是完全不可用的。**

### 10.2 「近场」的含义不同，且 A 篇的 2 m **不是** wt_inspection 的 2 m 量级

- A 篇：`d = 2 m` 是**到风机表面**（叶片/塔筒）的距离，用**禅思 H20 广角（DFOV 82.9°、等效焦距 4.5 mm）**，覆盖 `W_h × W_v = 3.35 × 2.51 m`。
- wt_inspection：站位距离由 `targetGsdMmPerPx` 反算，用 **M4T 三摄（广角 24 mm / 中焦 70 mm / 长焦 168 mm）**，长焦对角线视场只有 14.68°。
- **差异的量级**：同样要覆盖 2 m 宽的目标，H20 广角需 1.68 m，M4T 长焦需要 `2 / (2·tan(14.68°/2))` ≈ **7.8 m**（若按对角线算覆盖）—— 差 4~5 倍。**A 篇的 2 m 不能作为 wt_inspection 的站位距离参考。**
- 另一层差异：A 篇的「近场」动机是**图像清晰度**（拉近距离补分辨率不足），wt_inspection 的动机是**GSD 指标**（`target_gsd`）。前者是「尽可能近」，后者是「恰好够近」。

### 10.3 叶尖位置的来源：视觉识别 vs 台账 + 相位反解

- A 篇 §2.3 说叶尖位置「利用**计算机视觉和深度学习**等技术……进行识别和定位」，然后 `P_hub = (P_b1+P_b2+P_b3)/3`（式 2-6）。
- 但 §6.2 自己承认「**本文对风机轮毂的定位是假设已知的**」，且表 2-3 里三个叶尖是**写死的常数**。**两处矛盾。**
- 而且我复算过：这组「叶尖」**不共面、半径差 5.05 m**（37.86 / 39.33 / 42.91 m），**不可能是一台真实风机三个叶尖的坐标**。
- wt_inspection：叶尖/叶片位置来自 `WtTurbineSpec` 台账 + `WtTurbine_SolvePhaseFromTip` 相位反解（**接口存在但无人调用**）。⇒ **两边都"没有真正测到叶尖"**，但 wt_inspection 至少把这件事**写成了已知限制**，而 A 篇把它写成了「贡献」。

### 10.4 「对哪一点成像」

- A 篇：叶片中心线上的**垂足**（随无人机位置连续滑动）。
- wt_inspection：`waypointPoiPoint` 当前写死 `0,0,0`（`wt_bridge.c:403`）；`lz` 项目瞄的是**杆顶**（CLAUDE.md：「云台俯仰：瞄杆顶，不是中点」）。
- **三者指向三个不同的物理点。** A 篇的「投影点」甚至**不是叶片上的固定点** —— 它保证「镜头看向最近区域的轴线」，不保证「锁定某个损伤位置」。论文却称其解决「准确确认损伤位置」（§2.3.1）与「漏检」（摘要），**这个跳跃没有论证**。

### 10.5 关于「风轮转动」—— 与同批四篇一致，但 A 篇连声明都没有

A 篇全文（我 grep 过 `停转|停机|停用|转动|风轮|叶轮|风速|风场|湍流|尾流`）**没有任何一处讨论风轮是否转动**。叶尖坐标是常数、障碍物是静态点云、「最小距离」是到静态点云的距离 ⇒ **隐含前提是风机停机**。

同批四篇**也都假设风轮停转**，但至少把这件事当成一个需要处理的前提（相位反解就是为了确定停在哪）。**A 篇直接跳过了它** —— 因为它的路径以 `P_hub` 为中心展开，而 `P_hub` 又假设已知。

## 12. 关键原文摘录

> 「由于设计完全避开风机的路径太过复杂，故采用**直接连接**的方式，如图 2-6 的红色线条显示了**穿过轮毂**的部分路径，后续由改进 NMPC 轨迹跟踪算法的避障功能自动调整风机的位置，从而避开风机部件。」（印刷页 18）

> 「通过这一简化，改进的 NMPC 算法便可在保证安全性的前提下，对风机进行最大程度的近场巡检。」（印刷页 16）

> 「本文设定巡检时风机叶片的前缘或后缘始终面向风机前方。这样设计主要是为了简化路径生成过程，使得巡检任务更加高效。」（印刷页 17）

> 「当避障权重为 4 时，无人机与风机的最小距离为 0 米，这是因为**在路径规划中，为了简化算法设计，部分路径点位于风机内部**，导致无人机过于接近风机，表明此时避障项的影响较小，无法有效避免碰撞风险。」（印刷页 65）

> 「虽然设定的安全距离是 2 米，但当安全阈值也设为 2.0 米时，无人机与风机的最小距离为 **1.65 米**。这是因为无人机遇到障碍时，需要进行**速度缓冲和姿态调整，这些调整需要一定的时间**，因此在收到避障信号并开始减速时，无人机与风机的距离已经小于安全阈值。」（印刷页 66）

> 「然而，当前的仿真结果仅基于理论模型和设定的控制输入，所有的输入（如位置、速度和姿态）均通过模型预测和控制参数调节得出，**与 EKF 的估计结果无关**。未来的工作将引入 EKF 进行实时状态估计。」（印刷页 63）

> 「之所以选择不同时间段的数据，是因为……例如，在对 x 轴方向的位置进行估计时，最好选取无人机在 **x 轴方向位置点分布较分散**的时间区域……因此，通过选择合适的时间段，能够更好地展示传感器融合算法的性能。」（印刷页 53）

> 「**目前，本文对风机轮毂的定位是假设已知的**，这在实际应用中可能存在一定的局限性。」（印刷页 70）

> 「本文的研究目前主要基于仿真环境，虽然仿真结果验证了算法的有效性和鲁棒性，但在实际应用中仍可能存在一些未考虑到的问题。」（印刷页 70）

> 「由于无人机在主要巡检路径上飞行时，其三个欧拉角变化极小，且它们的值保持在 0 附近，因此**可以忽略无人机姿态对相机云台控制的影响**。」（印刷页 49）

> 「本实验最终调节选择的 `Q` 和 `R` 的值见式 (5-1)，此时，算得无人机在近场巡检风机的全程中，位置估计的均方根误差在 x 和 y 轴方向分别为 **0.23 m 和 0.24 m**，速度估计均方根误差在 x 和 y 轴方向均为 **0.04 m/s**。」（印刷页 59）

> 「改进 NMPC 算法能够在保证巡检精度的同时满足安全距离需求，**显著优于传统无人机巡检的 10 米距离要求**。」（印刷页 64）
