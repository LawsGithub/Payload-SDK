## 0. 结论先行

**五篇论文里，没有一篇解决 `wt_inspection` 的核心问题（风轮可转动时的安全规划），但有三篇独立指向了项目最明显的那个待办（停机相位未知），并且它们给出的方法恰好互补而不是互斥。**

三条最重要的判断：

1. **四篇论文全部假设风轮停转** `[V]`（B 篇 p11 明写"必须使风机处于停机工况"；D 篇依据 DL/T 797-2012 停机检修规程；C 篇叶片倾角定位依赖停转；E 篇 p45"首先要将整个风电场的风力发电机停转"）。**转动工况在文献里是空白** —— `wt_inspection` 的双模式安全判据没有外部可借鉴对象，这部分必须自己守。
2. **相位反解的三条路线是三层而不是三选一**：C/D 给「图像→叶片线」的检测，E 给「多帧→地理坐标」的解算，项目已有的 `WtTurbine_PhaseFromTip` 是判据。见 §3。
3. **真正的门槛不是算法，是取图**：`wt_inspection` 目前**没有任何图像获取能力** `[V]`（只有 `DjiCameraManager_StartShootPhoto` 触发快门，没有 liveview 订阅）。所有视觉类迁移建议都卡在这一步之前。

## 2. 代码核实：论文对项目的引用，哪些成立

五份报告都引用了 `wt_inspection` 的代码状态。我逐条查了源码，结果如下。

### 2.1 「相位反解无人调用」——方向对，细节要纠正 `[V]`

| 项 | 报告的说法 | 实际代码 |
|---|---|---|
| 函数名 | B 篇写 `WtTurbine_SolvePhaseFromTip` | 实为 **`WtTurbine_PhaseFromTip`**（`wt_turbine.h:122`） |
| 是否无人调用 | B/C/E 篇均称"无人调用" | **它被调用了** —— `wt_telemetry.c:111` |
| 真正无人调用的 | — | **`WtTelemetry_SolvePhaseFromVision`**：声明于 `wt_telemetry.h:97`、定义于 `wt_telemetry.c:75`，**全项目零调用者** |

**实际断链是四段，比报告描述的更长** `[V]`：

```
wt_app_config.c:327   park_phase 能被解析           ✅ 通
app/main.c:369        parkPhase = -1.0 硬编码       ❌ 断（注释：应由地面站经低速通道下发，该通道未实现）
wt_telemetry.c:75     SolvePhaseFromVision 无调用者  ❌ 断（判据在，喂数的接线没接）
wt_telemetry.c:116,154 rotor.phaseDeg 只被遥测内部消费，无路径回灌规划  ❌ 断
```

即：**配置解析了 → 主应用不用 → 视觉反解函数没人调 → 反解结果回不到规划**。任何"接通 park_phase"的动作都要补这四段，不是补一段。

### 2.2 「站位无入射角概念」——基本成立，但要区分两个不同的角 `[V]`

D 篇 §6.2 称项目"没有入射角约束"。核实结果：

- **没有**"视线与叶面法向夹角"这个概念 `[V]`（grep `入射角|incidence` 无命中）
- **但已有**一个相近的东西：`bladeAxialShiftM` / `WtPlan_BladeSkewAngleDeg`（`wt_plan.c:247`），定义是"沿叶片**轴向**的偏移比例"，上界 `WT_PLAN_AXIAL_SHIFT_MAX_FRAC = 0.50`，**约合 26.6° 斜视角** `[V]`

⚠️ **两者不是一回事**：轴向偏移是**站位沿叶片展向的错位**（为了拍到叶面而不是正对叶缘），入射角是**视线与目标表面法向的夹角**。D 篇建议的 30° 入射角上限与项目现有的 26.6° 斜视角**数值接近但语义不同**，迁移时不能互相替代，也不能简单相加。这是最容易被误读的一条。

### 2.3 「修补是离散采样，可改解析判交」——**建议不成立，应拒绝** `[V]`

D 篇 §6.4 建议用解析判交替代离散采样。`wt_plan.c:105-106` 的注释直接否掉了：

> 沿航段密集采样（步长取安全距离的一半，保证不漏掉窄的危险区），逐点套用与单点相同的判据。**相比解析求交，采样法对两种判据都适用**

项目有两种安全判据（静叶=点到轴线距离；转动=到旋转轴轴向分量），**解析判交只对前者有效**。采样是刻意的设计选择。D 篇自己也标了 `[?]`（存疑项 12："基于 README 描述，未读 `wt_plan.c` 源码确认"）—— 标注是诚实的，但结论应作废。

### 2.4 「项目有视觉模块」——**不存在，且连取图能力都没有** `[V]`

这是最重要的一条核实：

- `src/` `include/` 下与"视觉"沾边的**只有 `wt_camera.c/h`**，而它是**纯数学**（等效 35mm 画幅的 GSD / FOV / 重叠率换算），不含任何图像处理
- 全仓 grep `liveview`：**项目自身零命中**，只有 LICENSE.txt 的 SDK 目录树和官方 sample 提到 `dji_liveview.h`
- PSDK 侧唯一与相机相关的调用是**触发快门**：`DjiCameraManager_StartShootPhoto` / `SetMode` / `SetShootPhotoMode`（`wt_runner_psdk.c:164,257,262`）

**结论：项目能按快门，但收不到图像。** `psdk_lib/include/dji_liveview.h` 是现成的，但从未被使用。

⇒ 所有依赖图像的迁移（C/D/E 的相位反解、B 的视觉定位）**第一步都是新建取图链路**，这不是算法问题而是集成工程量问题。评估收益时必须把它算进去。

### 2.5 已证实成立的说法

| 说法（出处） | 核实 |
|---|---|
| 站位是解析布设、非自由采样（B/D 篇） | ✅ 成立（`wt_plan.h:58-59` overlapPct / bladeSpacingM 驱动解析布设） |
| 无覆盖率显式校验（B/D 篇） | ✅ 成立（有 `coverageM` 但那是"画面覆盖高度"的中间量，不是"目标被覆盖了多少"的核验） |
| 走 KMZ 预下发、不控轨迹（B/D 篇） | ✅ 成立 |
| 已有 `coneAngleDeg`/`tiltDeg` 参数（B 篇 §6.4） | ✅ 成立 |

## 3. 专题：停机相位反解的三条路线 —— 它们是三层，不是三选一

**C、D、E 三篇独立地把「停机相位未知」当核心问题**，而项目现状正是：`park_phase` 能解析但不接通，视觉反解接口零调用，默认按"叶片停在 12 点方向"假设并告警。这个待办的优先级应当上调。

三条路线拆开看：

| | C 王涛 | D 朱凯华 | E 潘佳捷 |
|---|---|---|---|
| 输入 | 单帧正视图 | 单帧正视图 | 3+ 帧多视角 |
| 方法 | HSV 分割 → Canny → 霍夫直线 | EDLines → 三步判别 | 前方交会 + 两参数停转反解 |
| 输出 | 叶片倾斜角 | 偏转角 γ = 90°−α | 叶尖地理坐标 + (r,p) |
| 判据核心 | 直线斜率 | **触底边且斜率≈90°的线=塔筒；塔筒顶端为圆心找互成120°的三线组=叶片** | 三叶 120° + 等长约束，把 12 维压成 2 维 |
| 需台账 | 否 | 需（模型=参考停机态） | 需 H/L/D |
| 需标定 | 内参 | 内参 | 内参 + 拍照姿态 |
| 精度 | 无量化 | 单样本 −29.75° | 10~20 cm（地面水瓶） |
| 计算量 | 极低 | 低 | 中（最小二乘迭代） |

### 关键洞察：它们处于不同层，应当串联

```
┌─ 检测层（C / D 提供）─────────────────────┐
│  单帧图像 → 叶片直线 / 叶尖像素坐标        │
│  C：HSV 去背景 + 霍夫（轻，无需台账）      │
│  D：EDLines + 塔筒/叶片的几何判别判据      │
└──────────────────┬────────────────────────┘
                   ↓ 叶尖像素坐标 + 拍照位姿 + 内参
┌─ 解算层（E 提供）─────────────────────────┐
│  多帧前方交会 → 叶尖 ENU 坐标 / (r,p)      │
│  两参数停转模型 + 射线距离残差最小二乘      │
└──────────────────┬────────────────────────┘
                   ↓ 叶尖 ENU
┌─ 判据层（项目已有）───────────────────────┐
│  WtTurbine_PhaseFromTip(spec, tipEnu, …)  │
│  ← 现成的、有测试的、纯几何的              │
└───────────────────────────────────────────┘
```

**E 的路线与现有接口同构**：`WtTurbine_PhaseFromTip` 接受的正是**叶尖 ENU 坐标**，E 的交会法产出的正是它。这是三条路线里唯一能直接对接既有判据的。

**C/D 的路线更轻但要补换算**：它们输出的是**图像角度**，需经相机模型 + 云台姿态换算成 ENU，或者绕过 `PhaseFromTip` 直接写相位 —— 后者会丢掉"判据在 wt_core 里、桌面可测"的分层优势。

**D 篇值钱的不是 EDLines**，而是它的**判别判据**（哪条线是塔筒、哪组线是叶片）—— 换任何边缘检测器都行，判据不变。

### ⚠️ 三条路线共同的前提，项目未必满足

1. **都需要取图**（见 §2.4，项目目前收不到图）
2. **C/D 都假设"正视图"**，而项目的粗模环绕阶段拍的是**环绕帧**，不是正视图 —— 要么新增一个"预检站位"（正对机舱），要么把判据改造成适应环绕视角
3. **E 需要 3+ 视角，相邻视线夹角有下限** —— 粗模环绕帧天然满足这一点，可复用、不新增飞行 `[?]`（但环绕帧的相机指向是否覆盖叶尖、画质是否够，未验证）

   ⚠️ **夹角阈值已由二次补读改写** `[V]`（E 篇 §10）：首轮报告写"45°~90° 最佳"，但补读把图 5-9 逐点数字化后发现——
   - 误差**从约 21°~26° 起就进入平台**（0.10~0.15 m），**一直平到 96° 不回升**
   - 真正的悬崖在 **≤16°**：11° 时误差棒上端已窜到 0.9~1.0 m，7° 中位数 0.72~0.95 m，1°~2° 达 **1.8~5.98 m**
   - ⇒ **"45°~90°"的上界没有数据支持**；90°~96° 同样可用，交会几何上接近正交反而更好

   **建议写成**：`相邻视线夹角 < 30° 拒绝解算、30°~45° 告警`，而不是照抄 45°~90° 闭区间。
4. **E 的 10~20 cm 是 3~9 m 外地面水瓶的精度**，几十米外叶尖在画面里只有几个像素，**不可直接外推**

### 一个 D 篇独有的迁移障碍（值得单独记）

D 篇的在线矫正**撞上 KMZ 落差**：识别出新相位后要么**重生成 + 重传 KMZ**（项目实测 41 分片链路），要么**预生成多档 KMZ 查表选择**（如每 30° 一档）。后者把在线计算变成在线查表，规避重算 —— 这是 PSDK 预下发模型下唯一现实的落地方式。

## 4. 迁移建议分级

### Tier 1 — 现在就该做（低成本、桌面可测、不依赖取图）

| # | 动作 | 来源 | 理由 |
|---|---|---|---|
| 1 | **接通 park_phase 四段断链**（§2.1） | 项目自身待办 + C/D/E 三篇佐证 | 三篇论文独立把它当核心问题，优先级应上调；接通本身不需要视觉，先把链路留出来 |
| 2 | **安全裕度的动力学欠账**（新增，见下方说明） | **A §6.1** | A 实测：避障阈值设 2.0 m → 实际最小距离只有 **1.65 m**，缺口 0.35 m，随阈值单调收窄、约 2.35 m 处过零 |
| 3 | **站位入射角检查 + 距离裕度报告** | D §6.2 | 但**必须先厘清**它与现有 `bladeAxialShiftM`（26.6° 斜视角）的语义差异，见 §2.2 |
| 4 | **覆盖率核验器**（站位×面元矩阵，输出未覆盖列表） | B §6.3 + D §6.3 | 把"全覆盖"从**推导结论**变成**逐点核验结论**；项目现在是构造性保证、缺独立验证器 |
| 5 | **危险航段修补的独立第二实现**（仅测试代码） | B §6.5 | 两个独立实现互检，符合项目"检查要能区分'做了'与'看起来做了'"的方法论 |
| 6 | **IMU 校准 + 偏航角与 RTK 航向交叉核对**进现场操作单 | E §6.3 | 近乎零成本；但 E 是 Phantom 4 单磁罗盘场景，M4T 双天线测向下 3° 量级可能不存在，**先测再定阈值** |
| 7 | **相机指向的纯几何算法**（新增，唯一不需要图像的视觉类条目） | **A §4.4** | "最近点→分区→中心线投影"，完全不需要图像/目标检测；可替换 `wt_bridge.c:404` 写死的 `waypointPoiPoint=0,0,0` |

**关于 #2（安全裕度）——为什么把它提到 Tier 1**：

`wt_plan.h:52` 的注释自己写着 `minSafeDistM` 是「**硬下限**：任何站位到任一叶片轴线不得小于该值」，也就是它被当作**几何上的保证值**在用。而 A 篇的仿真实测表明，**控制器跟踪时实际最小距离会比设定阈值小 0.35 m** —— 这个缺口是速度缓冲与姿态调整耗时造成的，**是动力学问题，不是几何问题**。

项目现状 `[V]`：`minSafeDistM` 默认 3.0（`wt_plan.c:432`），**全项目无任何随速度/高度变化的补偿项**；README 只在「转动模式」提了叶尖摆幅，**静叶模式完全没提**。

⚠️ **但不能直接照搬 0.35 m**：A 篇的机型、控制器（NMPC）、速度都与 M4T + KMZ 预下发不同。项目的执行模型是**飞控按航点直线插值飞行**，不是 NMPC 跟踪连续轨迹，误差机制不一样。**正确用法是先测自己平台的欠账，再定补偿** —— 这本身就是一个可做的实验。

## 5. 安全模型冲突：三套互不通用的语言

这是**最容易出错**的地方 —— 三篇论文各用一套安全几何，项目用的是第四套。

| 来源 | 安全模型 | 适用工况 |
|---|---|---|
| **B 单正文** | 轮毂中心为球心、叶长为半径的**球**（p10） | 停机锁定 |
| **D 朱凯华** | 面片法向距离带 **[4, 10] m** + 规划期静态碰撞检测 | 停机锁定（依 DL/T 797-2012） |
| **E 潘佳捷** | 无（只有"定位误差小 + 固定安全距离"两个抽象要求，自认没做避障） | 停机 |
| **C 王涛** | 无（5 m 贴飞，靠停机假设兜底） | 停机 |
| **wt_inspection** | 静叶：到叶片轴线距离 > `minSafeDistM`；**转动：保持叶轮圆盘之外**（轴向分量判据） | **两种都覆盖** |

**为什么不能混用**：B 篇的球模型在上下游方向远大于圆盘，而项目的圆盘判据只约束轴向分量、允许切向贴近 —— 两模型在轴向判据上甚至方向相反。照搬球模型会把项目的合法站位（圆盘边缘切向近距）误判为危险；反之亦然。

⚠️ **迁移任何"安全"结论前，必须先换算到项目的包线语言。** 这条建议本身没有例外。
