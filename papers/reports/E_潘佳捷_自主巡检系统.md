## 2. 一句话结论

`[V]` 论文提出并实现了一套"**地面站为核心**"的风机叶片自主巡检系统：用少量悬停取证照片 + 相机成像模型 + GPS/姿态信息，把 3 个叶尖和轮毂中心**前方交会**成地理坐标（多照片点到光线距离的最小二乘，CERES 求解），再据此生成叶片正反两面的悬停拍照航线；实测定位误差 10~20 cm 级。**它只做"定位 + 航线 + 拍照"，不做缺陷识别，也没有实机巡检验证**（作者自己在展望中承认，p65-66）。

## 3. 研究问题与定位

- **背景**（p1-4）：人工检修（望远镜、绳索垂降）成本高、效率低、有安全隐患；飞手手动操控则对技术要求高、漏拍误拍随机。自主巡检是热点，但"还缺乏针对无人机自主巡检的完备理论体系"（p10）。
- **切口**（p11）：核心问题被表述为"如何将风机转化为无人机可以感知的位置信息"——即**目标定位**。作者选择不依赖风机 CAD 模型、不依赖地面激光扫描，而是用**无人机自己拍几张照片**就把关键点算出来。这是全文唯一的创新支柱（摘要、结论反复强调"视觉测量算法的定位精度以及稳定性保证了系统可靠和高效"）。
- **前人现状**（p7-10）：综述了英国 Wales 大学（图像测距避障）、日本千叶大学（输电线 + GPS）、西班牙马德里理工（GPS 修正 + 视觉识别）、国网山东/冀北（直升机/无人机输电巡检）、中南大学（三次样条铁路巡检）等。与风机最接近的引用是文献[23]（控制模块 + 超声波测距控制云台/飞行/避障/拍照）。**没有引用任何"基于风机结构几何解析生成航线"的前人工作**——即 wt_inspection 那条"解析几何建风轮参考系"的路线，本文完全没走。
- **瞄准对象**：三叶型水平轴风机（p5-6），微观巡检（单台风机近距精细检查，p14）。

## 4. 技术路线与方法

### 4.1 系统架构（第二章，p13-23）

**机载/地面分工是"薄机载、重地面"** `[V]`（p16-17，图 2-4）：

```
无人机（采集 + 执行）                    地面站软件（全部计算）
├─ 机身模块（大疆 Phantom 4）            ├─ 预处理（相机标定/像素点采集/信息汇总）
├─ 飞控模块（RTK 定位 + 测向 + 航点飞行） ├─ 视觉测量算法（本论文核心）
└─ 云台模块（三轴增稳 + 可见光相机）      └─ 航迹规划（巡检点→巡航点→航线）
        ↑ 图传/数传 + SD 卡 交换数据 ↑
```

数据流 `[V]`（p15-16，图 2-2/2-3）：① 飞手操控无人机到风机前**多角度悬停拍照（取证飞行）**；② 照片 + 拍照时的位置/姿态（写在照片 EXIF / 飞控记录里）经图传数传或 SD 卡到地面站；③ 地面站算出 4 个关键点 → 等分出巡检点 → 设计巡航点 → 规划航线；④ 航线经数传下发给飞控；⑤ 无人机自主飞行悬停拍照。**机上不做任何计算**。

**硬件选型与理由** `[V]`：

| 项 | 选型/要求 | 页码 |
|---|---|---|
| 机型 | 大疆精灵四（Phantom 4，消费级），理由：轻、稳、便宜、自带前视避障和返航 | p18 |
| 定位 | **网络 RTK**（多基准站网状覆盖，单站失联可切换），要求水平/垂直误差 ≤ **3 cm** | p18-19, p14 |
| 云台 | 一体化三轴，俯仰 −90°~30°，偏航 −45°~45°，抖动误差 < 0.02°；**真实偏航 = 飞机偏航 + 云台相对偏航**（云台偏航相对机头） | p20-21 |
| 相机 | ≥ 1000 万像素，**固定焦距**（"变焦相机在无人机上变焦时会导致重心不稳……产生抖动"，p58）；拍照时位置/姿态写入照片 | p14, p20-21 |
| 作业需求 | 抗风 ≥ 10 m/s；续航 ≥ 20 min（单台风机不间断）；飞行高度 ≥ 300 m；机重 ≤ 20 kg | p14-15 |

**预处理模块**（p22-23）：① 张正友标定（OpenCV `findChessboardCorners` → `find4QuadCornerSubpix` → `calibrateCamera`），有出厂内参可直接用（p58-59）；② **像素点采集是人工的**——OpenCV 窗口里鼠标点击目标点（`setMouseCallback` + `on_mouse`）；③ 汇总到文本文件 `allParameter.txt` 作为算法唯一输入。

### 4.2 坐标系与转换（3.1 节，p24-31）

标准导航链条：WGS-84 大地坐标 → ECEF 地心坐标 → 当地 NED。要点：

- 高度：GPS 椭球高 h 与正高 H 差一个大地水准面差距 N（±100 m 内随重力分布变化），建议气压计辅助定高消除 `[V]`（p25-26）。
- 大地→ECEF 正算给出完整推导（式 3-9~3-11）：
  `x = (N+h)cosφcosλ, y = (N+h)cosφsinλ, z = [N(1−e²)+h]sinφ`，其中 `N = a/√(1−e²sin²φ)`。
- ECEF→大地**没有用闭式公式，而是迭代法** `[V]`（p30-31）：先设 `P'C = P'C'` 算初值 φ′，反算 `P'C'`，与假设值比较，超过阈值则循环，收敛后代回求 φ 与 h。
- 世界坐标系原点：**无人机起飞点（已知结构方案下是塔底）**，起飞前拍一张照记录其经纬度，转成 ECEF 记为 P_e0（p38, p46）。

### 4.3 视觉测量算法（3.2 节，p31-40）—— 全文核心

**单张照片 → 一条射线**。像素坐标 → 相机系 → 世界系方向向量：

1. 针孔模型 + 内参矩阵 K（式 3-20/3-35）：`[u,v,1]ᵀ = (1/zc)·K·Pc`，`K = [[fx,0,cx],[0,fy,cy],[0,0,1]]`。
2. 反解相机系坐标（式 3-36）：`Pc = zc·K⁻¹·Puv`，深度 zc 未知。
3. 世界系（机体 NED）下拍照点 + 方向（式 3-37）：`Pn = zc·Rcn·K⁻¹·Puv + T`，其中 `T = P_e1 − P_e0` 是相机在世界系中的位置（ECEF 差），`Rcn` 由无人机姿态角 (r,p,y) 构造——**注意还要叠加云台相对机身的姿态**（p43："相机的真实姿态角是在飞机的姿态基础上进行相对运动，所以需要两组姿态信息一起计算"；p60：真实偏航 = flight_yaw + gimbal_yaw）。
4. 消去 zc，得纯方向向量（式 3-39）：**`Mn = Rcn·K⁻¹·Puv`** —— 从光心指向"像素反投影的模拟关键点"。

**多照片联合 → 最小二乘**。单张照片一条射线一般不穿过真实点；两张照片两条射线可能近平行导致解飞掉（p39 明确讨论）；所以用 **N ≥ 3 个不同方向**拍照，每个方向得到一条过光心的向量 Mn_i，真实点 Pn0 到每条向量的距离用叉积表示（式 3-41）：

```
d = |Mn × Nn| / |Mn|     其中 Nn = T − Pn0（光心到真实点的向量）
```

联合最优化（式 3-42）：`min Σ d_i²`（论文写成分段三连加和的形式，疑似排版笔误，语义就是对全部距离平方求和 `[?]`）。

**求解**（3.3 节，p40-42）：非线性最小二乘，迭代求增量 Δx。介绍了线性搜索（高斯牛顿：`JᵀJ·Δx = −Jᵀg`，注明 JᵀJ 奇异/病态时不收敛）与信赖域法（ρ 接近 1 则扩域、过小则缩域，椭圆信赖域收敛更快）。**正文写"本系统中使用线性搜索法计算"（p40），但软件实现只说调 CERES 的 Options 求解（p43）**——CERES 默认是 LM（信赖域），两处说法不一致 `[?]`。软件侧用 C++ 结构体 `LineDistance3d` 封装"点到方向向量距离"残差块，输入即 `allParameter.txt`（p43）。

### 4.4 航迹规划（第四章，p45-54）

**总流程**（p45）：先**把整个风电场的风机停转** → 取证拍照 → 视觉测量定位 → 规划航线 → 自主巡检。**全程假设风机静止**，没有任何风轮转动场景的处理。

**分支一：风机结构已知**（4.2 节，p46-49）。结构参数三件套：塔高 H、叶片长 L、轮毂长 D（图 4-2）。停转状态用两个角描述：滚转 r（叶片在风轮平面内绕轴转）+ 偏航 p（整个机舱绕塔轴转），先滚转后偏航两次旋转组合即可表示任意停转位姿。三个叶尖的世界坐标闭式表达（式 4-1~4-3，世界系原点在塔底）：

```
W1(r,p) = (−D·cos p − L·sin r·sin p,  −D·sin p + L·sin r·cos p,  L·cos r − H)
W2(r,p) = (−D·cos p − L·sin(π/3+r)·sin p, −D·sin p + L·sin(π/3+r)·cos p, −L·cos(π/3+r) − H)
W3(r,p) = (−D·cos p − L·cos(π/6+r)·sin p, −D·sin p + L·cos(π/6+r)·cos p, L·sin(π/6+r) − H)
```

r、p 未知，最优化目标仍是"射线到对应关键点距离和最短"，且**隐含约束：三叶尖与轮毂中心两两相隔 120°、叶片等长**——把结构信息加进最优化，"计算出来的位置精度会更高"（p49）。解出 (r,p) 后整台风机所有点即可闭式算出。这本质是**用结构模型把 12 个未知量（4 点 × 3 维）压缩成 2 个**，是全文思路最像"工程解法"的一步。

**分支二：风机结构未知**（4.3 节，p49-53）。四个关键点（3 叶尖 + 轮毂中心）**各自独立**做视觉测量：每点 3 个角度拍照（相邻拍照方向夹角约 45°），每点 3 条射线做最小二乘，得到 4 个孤立点。然后**把每个叶尖与轮毂中心连线，把叶片简化为空间线段**，对线段等分分割得到巡检点（"距离越大，分割数量需要越多"，p52）。巡检点对应**正反两个巡航点**：由三个叶尖确定叶片平面法向量 n，沿 n 两侧偏移一个安全距离即得正/反面巡航点（p52-53）。航线形态：沿叶片往返、逐点悬停拍照（图 4-7）。

**航迹规划模块**（4.4 节，p53-54）：只有一张流程图——关键点 → 等分巡检点 → 两侧巡航点 → 巡航路线 → 数传下发。**没有安全校验逻辑的任何描述**（没有碰撞检测、没有扫掠区、没有限速限距检查），安全性完全寄托在"定位误差小 + 巡航点离叶片有安全距离"两件事上。

### 4.5 图像采集与拍摄触发

- 拍摄方式：到每个巡航点**悬停拍照**（云台增稳保证清晰度），没有速率触发/定时触发设计。
- 相机定焦 + 恒定大光圈 + 广角（p58），理由是变焦扰动重心、航拍距离远。
- 像素点采集**人工鼠标点击**——即取证照片中"哪个像素是叶尖"是人指的，论文没有任何自动检测叶片/叶尖的算法。
- 巡航点离叶片的距离：取实验得出的"最佳拍摄距离 5~10 m"（p63）。

### 4.6 缺陷识别

**没有。** 全文不含任何缺陷检测/识别内容；展望第一条承认"本视觉测量算法中并没有使用到高级图像处理相关的技术……如果使用现在更加成熟的计算机视觉相关技术，会让精度更加得到保证"（p65）——此处"计算机视觉技术"指的仍是把人工点选换成自动目标提取，而非缺陷识别。拍摄的照片是给人看的。

### 4.7 地面站软件

- 三模块（预处理/视觉测量/航迹规划），C++，OpenCV + CERES。
- 无界面设计描述、无数据库（展望第三条才提出"设计一个数据库进行备案，下次巡检直接调出"+ 历史照片对比，p66）。
- 数据接口是一个纯文本 `allParameter.txt`：每行 = 目标点 RTK 真值（TargetPointRTK）+ 照片名 + lat/lng/asl + gimbal_yaw/pitch/roll + flight_yaw + pixel_u/pixel_v（p60）。**输入、真值、输出格式全部在一个文件里**。

## 5. 实验与验证

**没有上真风机**。实验是地面标志物模拟（5.1 节，p55-60）：

- **实验设计**：空地上放两个标志物（红、蓝水瓶），相距 d1 ∈ {3, 5, 7} m（模拟叶片长度）；以各自为圆心、半径 d2 ∈ {3, 5, 7, 9} m 的圆弧上，等间隔取 7 个拍照方位（控制变量法）；圆弧相邻拍照点方位差即"拍照夹角"。另有**落地拍摄组 vs 飞行拍摄组**的对照，专门隔离"飞行抖动"这一个因素（p57-58）。
- **真值**：RTK 测量仪实地测标志物坐标（TargetPointRTK）。
- **结果**：
  - 第一次用某工业无人机（型号未写 `[?]`）+ 单基站 RTK："平均 50 cm 多"（p62）；单基站 RTK "有时会因为一些故障导致中途关机"，而系统要求连续作业（p61）。→ 换大疆精灵四 + 网络 RTK 重做。
  - 第二次（精灵四）：两照片夹角 45°~90° 时误差 10~20 cm；单点示例 A/B 两点误差 **0.045 m / 0.073 m**（p60，3 张照片、拍摄距离约 5 m、d1=3 m）。
- **定性结论**（p63-64，六条）：
  1. 相邻关键点间距 d1 对精度影响不大 → 大小风机通用；
  2. 拍摄距离 d2 影响不大，**5~10 m 效果较好**；
  3. **拍照方向夹角影响最大**：过小则两条射线近平行、解飞掉；45°~90° 误差小；
  4. 拍照次数：2 张易被单次偶然误差带飞，**3 张是精度/工作量最优**；
  5. 目标点靠照片中心误差小（边缘畸变）；
  6. 悬停稳定前提下，飞行抖动对精度影响可忽略（落地组 vs 飞行组对照）。
- **意外发现** `[V]`（p62）：不同地形磁场对**偏航角约有 3° 偏差**，不处理会导致最终误差 30~40 cm → 结论：**每次起飞前必须 IMU 校准**。
- 摘要宣称"定位精度可达厘米级别"（p.I），正文实测口径是 10 cm 左右（p11, p64）——"厘米级"是把 4.5~20 cm 都算进去的宽泛说法，**实际可靠精度应按 10~20 cm 理解** `[V]`。

## 6. ★ 可迁移到 wt_inspection 的条目

逐条：论文做法（页码）→ wt_inspection 现状 → 差异 → 迁移动作 → 代价与风险。

### 6.1（最高价值）用"取证照片 + 结构约束最优化"反解停转相位

- **论文做法**：已知 H/L/D 时，把 12 维未知量压缩为停转状态 (r,p) 两个量，用"射线到叶尖距离和最短 + 三叶 120° + 等长"做带约束最优化闭式求出叶尖坐标（p46-49，式 4-1~4-3）。未知结构时退化为 4 点独立交会（p49-53）。
- **wt_inspection 现状**：相位反解在 `wt_telemetry`（相位反解/滤波/外推），README 明言"相位视觉反解只提供接口，**目前无人调用**，故闭环叶尖跟踪尚未真正生效"；`park_phase` 未知时按"叶片停在 12 点方向"假设并告警。
- **差异**：wt_inspection 缺的正是一个"从图像反解 park_phase"的可实现方案。论文给了完整公式链（像素→K⁻¹→Rcn→射线→最优化），且证明了约束后的两参数模型在桌面级设备上能跑出 10~20 cm。
- **迁移动作**：把论文式 (4-1)~(4-3) 的"两参数停转模型 + 射线距离残差"作为 `wt_telemetry` 视觉反解接口的参考实现蓝本；按 wt_core 纪律，残差与最优化应写成纯 C 进 `wt_core`（不依赖 CERES——可以手写 2 维高斯牛顿，2 个未知量根本不需要通用求解器），用 PC 回归测试喂合成射线。叶尖像素坐标的来源可用 wt 视觉后端检测旗面/叶尖替代论文的人工鼠标点选。
- **代价与风险**：论文方案需要"取证飞行"（绕风机多角度拍 3+ 张）——wt_inspection 的两阶段路线（粗模环绕建模 → 精细巡检）**第一阶段本来就在环绕拍照**，取证可复用粗模阶段的帧，不新增飞行；风险是叶尖像素检测误差会被射线交会放大（论文没量化像素误差→定位误差的传递系数 `[?]`），且论文实验中风机是 3~7 m 外的水瓶，真机叶片在几十米外、叶尖在画面中只有几个像素，精度不可直接外推。

### 6.2 拍照几何的三条经验数字：夹角 45°~90°、拍摄距离 5~10 m、每点 3 张

- **论文做法**：p50、p63-64。两射线夹角过小是最小二乘病态的直接诱因（p39 还画了反例图 5-4）；5~10 m 是"最佳拍摄距离"；3 张是精度/成本最优点。
- **wt_inspection 现状**：站位间距由 GSD 与重叠率推导（`wt_camera` 的等效画幅 GSD、重叠率↔站位间距），这是"覆盖率"视角；**没有"多视角交会病态"视角**。若要启用叶尖跟踪/相位反解，站位摆放还需满足交会几何。
- **差异**：两条约束正交——重叠率保证"看得全"，夹角保证"算得准"。
- **迁移动作**：在 `wt_plan_demo` 的输出报告里加一项"反解几何检查"：对相位反解将用到的站位，计算相邻视线夹角，<45° 告警（论文数据）；同时把 3 视角最少张数写成 `wt_telemetry` 反解接口的前置校验（<3 条射线拒绝解算并给出 `LZ_ERR`-风格的明确错误码）。
- **代价与风险**：论文数字来自 3~9 m 近距、地面目标，对"几十米外的小目标"只有定性参考价值；夹角阈值应随现场标定，不能抄死。

### 6.3 磁场致偏航 3° → 误差放大到 30~40 cm → IMU 校准进起飞前检查单

- **论文做法**：p62 实测发现；p58 列为硬件纪律（"每次起飞作业前都要对无人机进行 IMU 校准……偏差几度都会导致最后结果相差很多"）。
- **wt_inspection 现状**：项目侧有一条类似的现场知识——M4T 用 RTK + 双天线测向，偏航精度远高于磁罗盘；但**云台偏航读数**（视觉对准依赖的 `TOPIC_GIMBAL_STATUS` 一类量）是否受磁场干扰未验证过 `[?]`。liangzhourenwu 项目的 ONDEVICE-CHECKLIST 有现场检查单，wt_inspection 侧未见对应物。
- **迁移动作**：若启用相位反解/视觉照准，把"起飞前 IMU 校准"与"核对偏航角与 RTK 航向一致性"写进 wt_inspection 的现场操作单；并在反解算法里对 flight_yaw 与 RTK 航向做交叉核对（差 >2° 告警）。
- **代价与风险**：几乎零成本；风险仅在于论文是 Phantom 4 单磁罗盘场景，M4T 双天线测向下该 3° 量级可能不存在——先测再定阈值。

### 6.4 架构反面教材：它的"薄机载、重地面"恰恰反证了 wt_inspection 全机载的难点在哪，也给出算力逃生门

- **论文做法**：机上零计算，全部视觉解算与规划在地面站 C++（OpenCV + CERES），靠图传/数传往返（p15-17）。
- **wt_inspection 现状**：全部机载（妙算3），理由是自主性；但妙算3 算力有限，且 PSDK 工作线程不能被阻塞（项目硬约束：回调只置标志）。
- **差异**：论文证明"重计算放地面 + 只传数据"在 2020 年的硬件上就够用；对 wt_inspection，PSDK 本身提供了把图像/数据回传 PC 或 Pilot 的通道。
- **迁移动作**：**不必改架构**，但值得把它记作"算力逃生门"：若妙算3 上相位反解/检测实时性不够，可在粗模阶段把少量关键帧经 PSDK 传回地面算（非实时、离线),结果再作为参数下发——这不破坏 wt_core 纯算法分层，因为算法本体仍在 wt_core。
- **代价与风险**：引入一条地面依赖，与"全流程机载"的项目目标相悖，只作为降级路径存在。

### 6.5 实验方法学：落地/飞行双对照组 + RTK 真值 + 控制变量

- **论文做法**：p55-64。所有可能影响精度的因素先枚举成 6 条（目标间距、拍摄距离、拍照夹角、拍照次数、目标在画面中的位置、飞行抖动），其中"抖动"用落地组 vs 飞行组隔离，其余用控制变量扫参；精度用 RTK 测量仪测的真值评估。
- **wt_inspection 现状**：`wt_plan_demo` + ctest 验证的是**规划器的数字自洽**，没有任何"实测精度评估协议"；相机标定、像素误差→相位误差的传递从未被测量。
- **迁移动作**：抄这套实验骨架——wt_inspection 首次现场验证视觉反解时，先做"地面标志物 + RTK 真值"的标定级实验（不用上风机），再上真机；把"关键点应位于画面中心区域"（畸变，结论 5）转化为视觉后端的有效 ROI 约束（丢弃边缘检测框或对边缘区域降权）。
- **代价与风险**：低成本；风险是论文的误差预算（10~20 cm）建立在人工点选像素（可以点得很准）之上，自动检测的像素噪声更大，精度只会更差。

### 6.6 单一文本接口的解耦（`allParameter.txt`）

- **论文做法**：p43, p60。视觉测量算法的全部输入（含 RTK 真值，用于评估）是一个纯文本文件；算法不接触任何硬件接口。
- **wt_inspection 现状**：wt_core 与 PSDK 的解耦靠"不 include dji 头文件"保证，但**测试输入没有统一的文件格式**，`wt_test_plan` 等用编译期数组。
- **迁移动作**：为相位反解设计一个类似的"射线记录"文本/CSV 格式（拍照位姿 + 像素坐标 + 内参 + 真值），让现场采集的数据能直接离线回灌进桌面回归测试——现场飞行一次，桌上验证一辈子。这与项目"参数唯一来源"原则同构。
- **代价与风险**：仅是约定，无风险。

### 6.7 ECEF→大地坐标的迭代反算：一个可对照的实现参考

- **论文做法**：p30-31，迭代法反算纬度（设初值→反算→比较→循环）。
- **wt_inspection 现状**：`wt_geometry` 已有 WGS-84↔ENU 切平面实现。
- **差异**：无实质差异，wt_inspection 的切平面法在作业半径（<1 km）内精度更高且无迭代。
- **迁移动作**：无需迁移；仅当需要把视觉测量结果与外部 ECEF 数据（如第三方 RTK 输出）交换时，确认对方用的是哪条链路即可。**列为"论文与现状重合、不构成增益"的项，避免重复建设。**

## 7. 与 wt_inspection 的冲突点

1. **安全模型完全不在一个层级** `[V]`。论文的前提是"**首先要将整个风电场的风力发电机停转**"（p45），全程静止；对安全只有"定位误差小"和"巡航点离叶片一个固定安全距离"两个抽象要求，**没有叶尖扫掠区、没有安全圆柱面、没有航段穿越检查、没有避障**（作者自认"没有针对性设计有关避障算法"，p65）。wt_inspection 的双模式安全判据（叶片静止/风轮可转动）与六类危险航段修补，论文一条都没有。**论文的航线生成思路不能整体照搬，只能借用其"关键点→等分→正反面巡航点"的几何骨架**，且必须先过 wt_plan 的安全校验。
2. **定位手段**：论文靠外置网络 RTK（3 cm 要求）+ 每次起飞前 IMU 校准；wt_inspection 的 M4T 自带 RTK 与双天线测向。论文对"定位误差如何进入航线安全裕度"没有建模（没有 min_safe_dist 与误差预算的关系式），而 wt_inspection 有 `min_safe_dist` 概念——迁移 6.1/6.2 时需自行补上"反解误差 → 安全距离增量"的换算，论文帮不上 `[?]`。
3. **精度宣称与实际的落差**：摘要"厘米级"（p.I）vs 正文 10~20 cm（p62-64），且实验目标是 3~9 m 外的地面水瓶，不是几十米外的叶片。若 wt_inspection 的叶尖跟踪需要比 10 cm 更好的相位精度（叶尖半径几十米时，10 cm 弧长对应的相位误差约 0.1~0.2°，尚可 `[?]`），需重新评估而不是引用论文数字。
4. **取证流程与作业模式冲突**：论文要求飞手先把无人机飞到风机前多角度悬停拍照（人工参与），wt_inspection 的目标是全自主。缓解见 6.1（复用粗模阶段帧），但粗模阶段的相机指向是否覆盖叶尖、画质是否够，wt_inspection 未验证 `[?]`。
5. **2020 年选型已过时**：Phantom 4（消费机）、人工鼠标点选像素、地面站 C++/OpenCV/CERES、无深度学习。特别是"人工点选"这一环在 wt_inspection 中必须换成自动检测（该项目视觉层正是自研 HSV 后端），论文对"像素误差如何传播到定位误差"没有给公式，这段要自己补。
6. **云台包线不同**：论文机型云台俯仰 −90°~30°、偏航 ±45°（p21），wt_inspection/GIMBAL 文档是俯仰 −90°~70°（M4T）。论文方案里"飞机比目标低时上仰"的余量问题在它的机型上更紧张，引用其拍摄几何时要换算到 M4T 的包线。

## 8. 存疑与未验证项

- `[?]` **求解器选择自相矛盾**：正文说"本系统中使用线性搜索法计算"（p40），软件实现只说用 CERES 的 `Options`（p43），而 CERES 默认 LM 属信赖域。论文没给任何收敛曲线/迭代次数数据。
- `[?]` **式 (3-42) 排版疑为笔误**：三项分段求和（i=1..N, j=1..N, k=1..N）语义不通，应是对全部 N 个距离平方求和；按语义理解，不影响方法本质。
- `[?]` 第一次实验的"工业无人机"型号、其 RTK 配置全文未写。
- `[?]` 相机内参数值（fx/fy/cx/cy）从未给出；标定结果只给了一张截图（图 5-5）。
- `[?]` 已知结构方案中，结构约束（120°/等长）"如何写进 CERES 的代价函数"没有给出代码或公式细节，只说了思想（p49）。
- `[?]` "相邻两次拍照方向向量夹角 45°~90°"的实验数据点分布（图 5-9~5-12 的横轴是角度）无法从文本还原，具体在 45° 与 90° 附近误差如何爬升未知；文本只说 45°~90° 之间误差 10~20 cm。
- `[?]` 巡航点与叶片的"安全距离"具体数值全文未给（只说"设定一个安全距离"p49、"根据后续实验确定的无人机飞行安全距离"p53；实验只给出拍摄距离 5~10 m 较优）。**5~10 m 是成像质量最优距离还是安全距离，两处在文中混用，未明确区分**。
- `[?]` 巡检点等分数量 N 如何随叶长确定只有一句话（"距离越大，分割数量需要越多"p52），无公式。
- `[?]` 磁场致 3° 偏航偏差是否已通过 IMU 校准消除、还是仍残留在结果里，文中未说清（先报 30~40 cm 误差，后说"起飞前要对无人机进行 IMU 校准"）。
- `[?]` 双天线测向仅一句提及（p59"无人机自带 RTK 以及双天线测向功能"），Phantom 4 标准版无双天线，应为 Phantom 4 RTK 版，论文未写明型号后缀。
- `[V]` 已逐字核对的部分：全部正文文本 + 用 pymupdf 复核了式 (4-1)~(4-3)（PDF p56）、第五章实验页（PDF p68-72）、系统组成页（PDF p23-24）。图 1-1~5-12 的**图形内容**（曲线形状、坐标轴刻度）无法从文本还原，凡涉及"从图上读数"的结论均已只采用正文文字表述。

## 9. 关键原文摘录

（页码为论文印刷页码）

1. **定位**（p11）："使用视觉测量算法，可以简单地利用航拍照片，结合拍照时的位置信息和姿态信息，结合最优化算法，能够比较精确地计算出巡检点实际所在的地理坐标位置。……得知该视觉测量算法可达到 10cm 级别精度。"

2. **硬件要求**（p14）："要求无人机导航定位的水平和垂直误差不能大于 3cm。……机载相机并不需要很高的像素，但是也不可低于 1000 万像素。同时相机调成固定焦距，对悬停航拍稳定性以及后续照片批量处理提供便捷。"

3. **系统分工**（p16-17）："该自主巡检系统主要包括两部分：无人机和地面站软件。无人机主要完成数据的采集以及基于航迹规划后的自主飞行，地面站软件主要负责数据的处理和航迹规划等任务。"

4. **视觉测量核心式**（p38-39）："`Mn = Rcn K⁻¹ Puv`……最终计算可以得出在世界坐标系下，光心到模拟关键点的向量……如果使用两张照片，……难免会由于两条向量接近平行，导致约束出来的点与实际 Pn0 点相差很远。所以需要通过多张照片联合计算。"

5. **单点测量几何**（p39）："设向量 Nn 是光心到真实关键点的空间向量……d = |Mn × Nn| / |Mn|"（式 3-41，点到射线距离用叉积）。

6. **结构约束反解停转状态**（p47-49）："设风机进行滚转运动之后停转状态……在经过一次滚转之后产生了一个 r 角……接着绕着塔身进行了一次偏航旋转，其中偏航角为 p……r 和 p 都是未知参数，需要再通过最优化的算法，按照在每条方向向量与对应关键点之间的距离总和达到最短条件下，建立最优化模型。……隐含了一个约束项，那就是 W1、W2 和 W3 三者与轮毂中心连线相差 120°的角度，且叶片长度相同。"

7. **未知结构退化**（p49-50）："将三个叶尖点与轮毂中心点单独使用视觉测量算法计算……相邻两次拍照的方向向量之间的角度大约在 45°到 90°之间最佳……最少需要 3 个角度的拍照才能保证精度。"

8. **叶片线段化**（p52）："将三个叶尖与轮毂中心分别连接视为叶片……对每一条连线进行等分分割，分割的数量根据叶尖点与轮毂中心的距离而定，距离越大，分割数量需要越多。……向量 n 表示风机叶片平面的法向量。可以通过三个叶尖确定一个平面的法向量，利用法向量确定巡航点在叶片的正反面坐标。"

9. **第一次实验失败**（p61-62）："最开始使用的是一款工业无人机，体型较大，灵活度不够，在悬停拍摄时不够稳定，且使用的是单基站 RTK，有时会因为一些故障导致中途关机，但是本系统要求连续作业……由于最终结果所示误差都比较大，平均 50cm 多。"

10. **磁场发现**（p62）："不同地形对于无人机的姿态角计算会产生影响，由于磁场的作用，对于偏航角会有大约 3°左右的偏差影响，如果不处理会导致最终计算误差达到 30cm 到 40cm，不利于安全自主飞行。所以在实际作业过程中，起飞前要对无人机进行 IMU 校准。"

11. **六条结论**（p63-64）："两次用于计算的拍照的方向夹角会对精度有一定的影响，角度过小会导致误差很大，角度范围在 45°到 90°之间，对精度的影响会比较小。……经过落地实验和飞行实验进行比较，在保证无人机的悬停拍照稳定性前提下，飞行作业的飞机抖动对于精度影响可以忽略不计。"

12. **自认不足**（p65-66）："本视觉测量算法中并没有使用到高级图像处理相关的技术……还缺少实际对风机进行巡检的验证过程。……没有针对性设计有关避障算法。……可以将每个风机的巡检的数据进行记录，设计一个数据库进行备案，下次巡检时可以方便调出。"

### 附：给主报告的一句话素材

这篇 2020 年论文是"**定位问题**"的纵深（照片→射线→最小二乘→停转相位），而非"巡检系统问题"的广度——它没有缺陷识别、没有实机验证、没有安全模型；但它对 wt_inspection 最缺的一环（相位视觉反解接口无人调用）恰好提供了一份带公式、带实测误差数字、带实验设计的参考实现蓝本，其"结构约束把 12 维压缩成 2 维"的思想与实验方法学（落地/飞行对照组、RTK 真值、夹角扫描）比其最终精度数字更值钱。

### 对正文的更正（本次读图逼出来的）

1. **图 5-9~5-12 的横轴不是角度，是拍摄距离 `distance/米`。** §4.5、§5、§6.2 反复把图 5-9~5-12 并称"实验曲线（横轴是角度）"，§8 也写"图 5-9~5-12 的横轴是角度"。实测：**只有图 5-9 的横轴是 `Angle/度`；图 5-10/5-11/5-12 的横轴都是 `distance/米`**（横轴范围分别是 3~7 m、4~18 m、4~24 m）。这三张图回答的是"**拍摄距离**如何影响误差"，不是"夹角如何影响误差"。**夹角与误差的关系只有图 5-9（精灵四）与图 5-8（工业无人机）两张图**。
2. **"45°~90° 是最佳夹角区间"这个说法在图上没有上界依据。** 图 5-9 显示 46°~96° 是一条平线（0.10~0.13 m），**96° 处没有任何回升**；图 5-8（工业无人机）同样平到 96°。论文正文写的"角度范围在 45° 到 90° 之间对精度的影响会比较小"应理解为"**≥45° 即可**"，而非"45°~90° 这个闭区间最好"。**wt_inspection 若要设阈值，只应设下限，不应设上限。**
3. **正文 §5 说"以各自为圆心…等间隔取 7 个拍照方位"，但图 5-1 画的是 A₁~A₅、B₁~B₅ 共 5 个；而 p58 的正文又写"在圆弧上等分为 7 组进行拍摄"。** 图与正文（以及正文自身前后）不一致。图 5-9 横轴每 5° 一个点、共到 96°，与"7 个方位"也对不上（7 个方位分不出 19 个角度的数据点）。**⇒ 数据点的真实方位数不可考，报告 §5 里"7 个拍照方位"应改标 `[?]`。**
4. **§8 里"图 5-13/5-14 实验场景照片"的图号不存在** —— 第五章图号止于 5-12。实验场景照片是**图 5-2 / 图 5-3**（PDF p64）。任务书里"图 5-13/5-14"的说法应作废。
