## 2. 一句话结论

针对"叶片缺陷样本稀缺"与"人工操控无人机效率低"两个问题，提出三件套：**VAML**
（VAE + 元学习的小样本缺陷检测，5 张图即可检测）、**UDST**（Swin Transformer GAN
的无监督缺陷检测，零缺陷样本即可训练）、**视觉自主巡检方法**（YOLOv5s 定位轮毂 →
HSV 分割 + 霍夫变换定位停机叶片 → 沿叶面直线飞行的路径规划，配 ROS/PX4 控制系统），
前两者在 RTX2080Ti 离线验证，第三者仅在 Gazebo 仿真中验证——**从未上真机**。

## 3. 研究问题与定位

**前人做到哪**（第 1 章）：
- 深度学习缺陷检测已成熟但要求数据充足（Wang 的 Haar-like+集成分类器、Shihavuddin
  的多网络自动标注、Panizza 的 RetinaNet、Xin 的 EfficientDet 改进等，印刷页 3-4）；
- 小样本检测四条路（数据增强/度量学习/迁移学习/元学习，印刷页 5-7）；
- 无监督检测基于图像重建（AE / GAN，印刷页 7-8）；
- 无人机巡检：无人机 1.5 小时 vs 人工 8 小时（引 Nergica 报告，印刷页 8）；Picchi 用
  测距传感器控制无人机沿叶片飞、Stokkeland 用视觉估计叶片位置（印刷页 8）。

**它的切口**：
1. 缺陷数据不够 → 元学习里"类别注意力向量靠支持集样本特征加权平均，样本质量差
   会把向量带偏"（印刷页 20，图 3-1）→ 用 VAE 学潜在分布再采样，替代简单平均；
2. 极端情况下某类缺陷一张样本都采不到 → 监督方法无能为力 → 只用无缺陷样本的
   重建式无监督检测；
3. 人工飞无人机难 → 视觉自主巡检。针对"现有霍夫变换方法在背景中检出过多直线"
   （印刷页 44），先做 HSV 分割去背景再做霍夫。

**定位判断**：这是典型的"算法章 + 算法章 + 系统章"硕士论文结构。第 3、4 章是
CV 算法贡献（在 PC/服务器上做），第 5 章是巡检系统（仿真做），**三条线之间的
耦合很松**：第 5 章的巡检只采集图像，并不调用第 3、4 章的检测模型。

## 4. 技术路线与方法

### 4.1 第 3 章：VAML —— VAE + 元学习的小样本缺陷检测（印刷页 20-32）

**基座**：Meta R-CNN（Yan et al., ICCV 2019）[V]（印刷页 21）。

**整体结构**（印刷页 21，图 3-2）：骨干网络（ResNet-101，ImageNet 预训练）同时
输入支持集与查询集，输出 Fs / Fq；随后两路：
- Fq 过**交叉参考模块**增强 → RPN → RoI Pooling；
- Fs 过**采样特征模块**（VAE）→ 采样出类别注意力向量 z → 与 RoI 特征聚合；
- 检测头输出分类 + 回归，损失为交叉熵 LCE + 平滑 L1 LSmooth [V]（印刷页 21-22）。

**交叉参考模块**（印刷页 22-23）：全局平均池化 + 两层全连接（1024 隐藏单元，均
Sigmoid），分别把 Fs、Fq 压成通道激活向量 fs、fq，点乘得融合向量 fc，再对 Fq 逐
通道加权（式 3-2、3-3）。动机：让查询特征中"与支持集共同存在的前景表示"权重更高，
**提升 RPN 的前景/背景判别能力**——即用支持集当模板在查询图上"找相似"，避免 RPN
漏提。

**采样特征模块**（印刷页 23-25）：借零样本学习中 VAE 的思想。Encoder/Decoder 各
为三层全连接（1024 隐藏单元），Encoder 把 Fs 映射到高斯分布 N(μ,σ²)，重参数化
z = μ + σ·ε（式 3-4），z 作为类别注意力向量与 RoI 特征逐通道点积（式 3-5）；
Decoder 重构 Fs′，用 MSE 损失（式 3-6）+ KL 散度损失（式 3-7）训练。动机：简单
加权平均出的类别注意力向量会被"特征差异大的个别样本"带偏，从学到的**分布**里
采样则对样本质量鲁棒。

**训练流程**（印刷页 22，式 3-1）：标准两阶段小样本协议——第一阶段只在基础类上
以 N-way K-shot 元任务训练；第二阶段在基础类+新类的平衡集（每类 K 个）上微调。
K ∈ {1,2,3,5,10} [V]（印刷页 25，表 3-1）。

**训练配置** [V]（印刷页 25-26）：PyTorch，Ubuntu 20.04.3，Xeon E5-2678 v3 +
RTX 2080Ti；SGD，batch 8；第一阶段 lr 0.01、15000 迭代；第二阶段 lr 0.001、
1500 迭代。

**对比方法**：Meta R-CNN、TFA、FSCE、FSDetView、DCNet（检测器均为 Faster
R-CNN）[V]（印刷页 25）。

**评价指标**：mAP50（IoU=0.5）[V]（印刷页 26）。

### 4.3 第 4 章：UDST —— 基于 Swin Transformer 的无监督缺陷检测（印刷页 33-43）

**思想**：GAN 图像重建式异常检测——只用**无缺陷**样本训练；测试时生成器把缺陷
图像"修复"成正常图像，比对原图与重建图定位缺陷。

**生成器**（印刷页 34-35，图 4-2）三段：
1. 浅层特征提取：单层卷积映射到高维空间；
2. 深层特征提取：堆叠多个带**残差结构**的 Swin Transformer 块（窗口自注意力 +
   移位窗口自注意力，含相对位置偏置 B 的 Attention 公式 4-1）；
3. 图像重建：PixelShuffle 上采样重构高分辨率图像。

**判别器**（印刷页 36，图 4-3）：**U-Net 结构**（引 Schonfeld 的 U-Net GAN 判别
器），Encoder 编码全局信息、Decoder 解码局部信息，跳跃连接兼顾浅层边缘与高层
语义。

**掩膜操作**（印刷页 36-37，图 4-4）：训练时对输入图随机加掩膜，**掩盖 50%**，
三种尺度、两两互补（交换被遮盖/无遮盖区域），被遮区域像素置 0。理由：掩膜太小
则重建结果仍受邻近缺陷影响，太大则信息不足；50% 经消融最优（印刷页 42，图 4-8）。

**缺陷定位**（印刷页 37）：SSIM 逐像素比较原图与重建图（亮度/对比度/结构三要素
加权乘积，式 4-2），再用 OpenCV 阈值分割二值化 + 轮廓提取得到缺陷区域。

**训练配置** [V]（印刷页 38）：PyTorch，同 2080Ti 服务器；SGD，700 epochs，
动量 0.9，权重衰减 1e-4，初始 lr 0.003 指数衰减（按 0.9 幂率）。

**评价指标**（印刷页 38-39）：像素级 Precision / Recall / IoU（TP/FP/FN 按像素
定义，式 4-3~4-5）。**注意这不是检测框 mAP，是分割级指标。**

**对比方法**：AE-SSIM、GradVAE、AnoGAN、DAGAN、GANomaly [V]（印刷页 38）。

### 4.4 第 5 章：无人机自主巡检方法（印刷页 44-58）—— 对 wt_inspection 最相关

#### 4.4.1 初始作业点定位（印刷页 44-45）

- YOLOv5**s**（考虑实时性选最小号），COCO 预训练权重微调，**lr 1e-5** [V]
  （印刷页 54）；
- 流程（图 5-1）：**人工把无人机摆到待检风机正前方** → 垂直起飞 → 上升过程中
  逐帧检测轮毂 → 轮毂出现后按比例控制微调：
  `u = kc·(Ix − Fx)，v = kc·(Iy − Fy)`（式 5-1），其中 (Fx,Fy) 是轮毂中心像素
  坐标、(Ix,Iy) 图像中心，kc 为调节系数（避免远处调节过慢）；
- 轮毂前方位置即"初始作业点"。

#### 4.4.2 风机叶片定位（印刷页 46-48）

三步流水线，明确排除了两条替代路：传统霍夫直接做（背景直线太多）、U-Net 语义
分割（要大量标注）：
1. **HSV 色彩模型分割风机**：RGB→HSV（式 5-2），设阈值取前景掩码，OpenCV 实现，
   把白色风机从野外背景中提取出来（图 5-3）；
2. **Canny 边缘检测**：Sobel 3×3 算子求梯度（式 5-3）；
3. **霍夫变换直线检测**：在二值边缘图上找叶片边缘直线，斜率即叶片倾斜角度。

对比图（图 5-4）显示：直接 Canny 引入大量背景干扰；先 HSV 分割再 Canny 则风机
区域干净 [V]（印刷页 47-48）。

> ⚠️ **图 5-2 的流程图是四步，比正文多一步"过滤直线"**（HSV 分割 → Canny → 霍夫 →
> **过滤直线**）。正文从未提这一步，但图 5-5 显示霍夫确实在塔筒两侧各出了一条竖直
> 直线，说明过滤是必需的。见 §10.1 更正 6。

#### 4.4.3 巡检路径规划（印刷页 49）

- 在**机体坐标系**下规划：以叶片边缘斜率为参考，控制无人机**沿直线飞行**；
- 流程：飞至叶片正面 → **"控制无人机旋转并飞至叶片背面"** → 继续沿直线飞行 →
  重复直至三个叶片的正面+背面全部完成（印刷页 49）；
- ⚠️ 就这两句话。**没有**站位概念、没有重叠率、没有拍摄距离与 GSD 的推导、没有
  换面段的安全路径描述、没有与叶片保持什么距离的公式——"结合叶片位置和长度信息"
  一句带过。

#### 4.4.4 无人机巡检控制系统（印刷页 49-52）

- **硬件/软件栈**：Jetson TX2 板载计算机 + Ubuntu 16.04 + ROS Kinetic + PX4 开源
  飞控 + MAVLink 协议 [V]（印刷页 50）；
- **架构**：话题（topic）通信的发布/订阅模式；**5 个功能节点** [V]（印刷页 52）：
  1. 轮毂定位节点：订阅图像 → YOLOv5s → 发布轮毂中心相对位置与框宽高；
  2. 叶片定位节点：订阅图像 → HSV 分割 → Canny + 霍夫 → 发布**三个叶片倾斜角度**；
  3. 路径规划节点：订阅检测结果与无人机状态 → 无轮毂则垂直上升，有则算运动量与
     期望位置（用叶片倾斜角度 + 叶片长度）→ 发布下一目标位置；
  4. 控制节点：订阅期望位置 → 发布位置/速度/加速度控制指令；
  5. 状态节点：订阅状态消息打印。

### 4.5 边缘部署（唯一的机载推理讨论，印刷页 54）

- 目标机：**Jetson TX2**；
- 手段：PyTorch → ONNX → **TensorRT**；
- 结果：YOLOv5s 转换后在板载计算机上**27 FPS** [V]；
- 就这一段。没有 INT8 量化、没有精度损失对比、没有第 3/4 章模型（Faster R-CNN 系、
  Swin GAN）的机载部署讨论——**两阶段检测器和 Swin GAN 都太重，论文没敢往板上放**，
  板上只跑了 YOLOv5s 一个模型。

## 6. ★ 可迁移到 wt_inspection 的条目

先摆结论：**这篇论文的检测模型（第 3、4 章）对 wt_inspection 基本不可迁移**——
wt_inspection 只做航线规划不做缺陷检测，且妙算3 的算力与 PSDK 环境跑不动
Faster R-CNN 系和 Swin GAN；论文自己也没把这两个模型部署到板上。**真正有价值的
是第 5 章的采集与感知假设**，它能反推 wt_inspection 的航线规划该给下游检测留下
什么；以及一条与 wt_inspection 现状直接对口的视觉相位解算方法。

### 6.1（最有价值）HSV 分割 + Canny + 霍夫解算停机叶片相位——直接补 wt_inspection 的"相位无人调用"缺口

- **论文做法** [V]（印刷页 46-48）：RGB→HSV 阈值分割把白色风机从背景提出（去
  背景直线干扰）→ Canny → 霍夫直线检测 → 边缘直线斜率 = 叶片倾斜角度，输出
  **三个叶片各自的倾斜角度**（ROS 消息，印刷页 52）。全程 OpenCV 传统算法，
  无需训练数据。
- **wt_inspection 现状**（README「已知限制」）：停用角未知时按"叶片停在 12 点
  方向"假设并告警；`wt_telemetry` 的相位反解只提供接口、无人调用；像素级换算
  需视觉模块接入内参。
- **差异**：论文证明了一条零训练成本的相位感知路——wt_inspection 已有完整的风轮
  参考系与相位反解框架，缺的只是"从图像到相位角"的那一环，论文这 2 页就是这个
  环节的可运行配方。
- **具体动作**：在 wt_core 新增一个纯算法模块（如 `wt_phase_visual.c`）：输入
  图像帧 + 相机内参 + 云台姿态，走 HSV→Canny→Hough 输出叶片轴向角，再经
  `wt_telemetry` 既有接口换算成风轮相位；配合 wt_inspection 已有的"停机相位"假设
  形成"假设值 vs 视觉实测值"的双源校验（两值不一致时拒绝起飞或告警）——这正好
  满足 CLAUDE.md 里"只有 auto_start=true 才硬性拒绝"之外的人工确认需求。
- **代价与风险**：HSV 阈值依赖叶片颜色（多数叶片白色/浅灰，与天空/地面可分，但
  雪地/云层背景会失效——论文没做任何鲁棒性量化）；霍夫直线在塔筒、机舱边缘也
  会出线，论文靠"先 HSV 分割"缓解但未给出误检率数字；解算距离与视角未约定，
  接入 wt_inspection 时需规定"在初始作业点（轮毂前方）拍摄"以固定几何关系。

### 6.2 巡检几何给出了"贴叶直线飞行"的参数锚点：5 m 距离 + 1 m/s + 单面 48 s

- **论文做法** [V]（印刷页 56）：叶片 43 m 的风机，巡检时**距风机约 5 m 沿叶片
  轴向直线飞**，1 m/s，单叶片单面约 48 s（≈48 m 行程，与 43 m 叶长自洽），
  正反两面 × 3 叶片。
- **wt_inspection 现状**：三阶段航线规划，站位由等效画幅 GSD 与重叠率推导
  （`WtPlan_ResolveBladeSampling()`），巡检模式区分"叶片静止/风轮可转动"，安全
  判据是到叶片轴线（或旋转轴）的距离 > min_safe_dist。
- **差异**：论文的"5 m"是唯一给出的拍摄距离数字，但**没有任何 GSD 推导支撑**——
  5 m 距离下 1920×1080 画幅的像素 GSD 完全取决于变焦倍数，论文没写。它不能作为
  wt_inspection 的参数来源（违反"文档数字必须由规划器产出"的项目铁律），但可以
  作为**量级交叉校验**：wt_inspection 若在叶片静止模式下产出 5~10 m 的贴叶站位
  距离、1 m/s 级的巡航速度、单叶 1~2 分钟量级的巡检时间，与论文的仿真量级一致，
  说明双方都在合理区间。
- **具体动作**：把"单叶片单面 48 s @ 1 m/s、距叶面 5 m、叶长 43 m"记为一条外部
  参照锚点（写进 wt_plan_demo 的对照输出或 README 的量级校验段），规划器数字与
  它差一个数量级时触发人工检查。不改代码逻辑，只加一条对照测试/注释。
- **代价与风险**：论文是仿真数字（Gazebo 理想环境），且 5 m 是"距风机"不是
  "距叶面"，机翼扫掠、塔筒距离都没区分；只能当量级参照，不能当设计输入。

### 6.3 采集要求的"隐含约束"反推：论文暴露的正是 wt_inspection 的强项面

- **论文现状** [V]：全篇（含 WSD 数据集采集描述，印刷页 27-28）**没有出现**
  GSD、重叠率、拍摄距离与缺陷尺寸的关系、曝光/光照要求中的任何一项推导。第 5 章
  路径规划"以叶片边缘斜率为参考沿直线飞行"，配合 27 FPS 的检测帧率（印刷页 54），
  隐含的采集约束只是"帧率够、不糊、叶面覆盖完整"。
- **对 wt_inspection 的意义**：如果将来 wt_inspection 要把"采集的图像喂给检测
  模型"纳入航线设计目标，这篇论文**给不出任何可用的采集规格**——缺陷检测文献里
  常见的"缺陷最小可分辨尺寸 → GSD → 拍摄距离"链条它没有做。这反而说明
  wt_inspection 现有的"等效画幅 GSD + 重叠率↔站位间距"推导（`wt_camera`）在同类
  工作中是更完整的一环；迁移方向是**反向**的：wt_inspection 可以把自己推导的
  GSD/重叠率作为"检测需求输入"的模板，而不是从这篇论文里找需求。
- **具体动作**：无需改代码。若后续项目文档要引外部工作支撑"采集参数必须由规划
  推导"，这篇论文可作为反例引用（"同类学位论文未做此推导"）。
- **代价与风险**：无。

### 6.4 无监督检测（UDST）作为"未来加检测功能"的路线提示：只需无缺陷样本

- **论文做法** [V]（印刷页 33-37）：只用无缺陷样本训练重建 GAN，测试时比对
  SSIM 定位缺陷，像素级 IoU 28~47%（WSD/MVTec 子集）；对小样本方法（5 张图）
  的 VAML 则需 5 张标注图。
- **wt_inspection 现状**：不做检测；但项目终局（巡检→缺陷报告）若要补检测环节，
  数据获取是最现实的瓶颈（论文第 1 章的立论恰恰是"缺陷样本难采"，印刷页 2）。
- **差异**：UDST 的"零缺陷样本"训练协议对运维场景现实——每台风机每天飞出来的
  正常叶面图就是训练集。但模型是 Swin+GAN，**妙算3 上不可能实时跑**（论文自己
  也只在 2080Ti 上离线跑），只能落地回传后离线批处理。
- **具体动作**：仅作路线备忘，写入 wt_inspection README「已知限制」附近的"未来
  扩展"段落（若存在）即可；不需要任何当前动作。
- **代价与风险**：论文的像素级指标（IoU ~30-45%）离运维可用还很远；且其消融
  显示"特征不明显的缺陷类别误判多"（印刷页 41），表面磨损类恰是叶片最常见缺陷
  ——不能按论文结论章的乐观口径评估。

### 6.5 轮毂检测 + 比例控制对准初始作业点：与 wt_inspection 的"初始作业点"概念对得上

- **论文做法** [V]（印刷页 44-45）：垂直起飞过程中 YOLOv5s 检测轮毂，用
  `u=kc(Ix−Fx)` 的比例控制把机体对准轮毂正前方；27 FPS（TX2 + TensorRT）。
- **wt_inspection 现状**：航线是预先生成的 KMZ/wpml，初始作业点由规划器给出；
  无飞行中的视觉对准环节。
- **差异**：wt_inspection 的规划起点依赖"机组 GPS 坐标 + 轮毂高度"等配置输入；
  论文提供的是"输入不准时的视觉自校正"思路。PSDK 侧有实时取图能力
  （`dji_liveview.h`）与 `dji_fc_subscription` 位姿订阅，技术上做得到"飞到轮毂
  前方附近→视觉确认→微调"，但需要把控制量下发给航线（waypoint v3 是预下发模式，
  不适合做逐帧伺服；更贴近的是 PSDK 的飞行控制接口，那是另一条集成路）。
- **具体动作**：暂不迁移。可作为"phase 反解视觉模块"（见 6.1）的后续扩展：
  先在悬停点做视觉确认相位，不涉及实时伺服。
- **代价与风险**：实时视觉伺服与"预下发 KMZ"的作业模型冲突，硬做要引入
  PSDK 停速/接管逻辑，工程量与安全风险都大；论文只在仿真里验证过，无真机数据。

## 7. 与 wt_inspection 的冲突点

| 论文假设 | wt_inspection 约束 | 冲突性质 |
|---|---|---|
| 飞控栈是 **PX4 + MAVLink + ROS**（印刷页 50），控制节点直接发位置/速度/加速度指令 | 主体是 **DJI M4T + PSDK**，航线走 KMZ/wpml 预下发，PSDK 不开放底层位置环 | 根本架构冲突：论文的"实时视觉伺服巡检"在 PSDK 上没有对应控制通道，只有预下发航线一条路（waypoint v3） |
| 板载计算机 **Jetson TX2**（~1.3 TFLOPS 量级），YOLOv5s@TensorRT 27 FPS | 妙算3，算力规格未公开对标；且 wt_core 分层纪律禁止把重型推理放进航线关键路径 | 部署环境不同；论文的 27 FPS 数字不能外推到妙算3 |
| 巡检全程假设**风轮停转**（叶片角度固定，才可用霍夫斜率定位叶片） | wt_inspection 的核心安全设计恰恰是"风轮可能转动时叶片位置无意义"，区分两模式并修补扫掠区危险航段 | 论文完全没有处理风轮转动的情形；其巡检流程若在 wt_inspection 的"风轮可转动"模式下执行会撞叶尖 |
| "控制无人机旋转并飞至叶片背面"（印刷页 49）一句带过换面 | wt_inspection 的危险航段修补（双面换面段擦过叶尖等六类）正是为此设计 | 论文对最危险的换面段零讨论；不能借它的流程省掉 wt_inspection 的修补逻辑 |
| 5 m 距离贴飞，无安全包线概念（叶长 43 m，5 m 已在叶尖扫掠半径内——靠"停机"假设兜底） | min_safe_dist 安全包线是硬约束，转动模式下需按风速放大 | 若把 5 m 当"距叶面"距离，在叶片静止模式下或可接受（与 wt_plan 的静止判据兼容，需按叶轴距离校验）；在转动模式下绝对不可 |
| 检测指标是 mAP50/像素 IoU，无 FPS 之外的作业级指标（漏检后果、复飞策略） | wt_inspection 的规划层"出错代价最大必须桌面可验证" | 理念差异：论文重模型指标，wt_inspection 重安全与可验证性；引用其结论时要注意口径不同 |

### 10.1 对正文的更正（本次读图新发现，均与报告正文的既有说法冲突）

**更正 1（最重要）：§5.1 里 WSD 的 1-shot / 5-shot 数值被对调了** `[V]`

报告 §5.1 现在写的是「1-shot：新类 33.6、基础类 89.2；5-shot：只在图 3-7 里，正文未给」。
**这个归属是错的**，判据有三条，互相独立：

1. **图题**：33.6 与 89.2 这组数字出现在 **图 3-7**，其图题明确是「图 3-7 **5shot** 的实验结果」
   （PDF p40）。图 3-6（PDF p39）的图题是「图 3-6 **1shot** 的实验结果」，它的 nAP 是 **48.8**、
   bAP 是 **89.2**。
2. **算术**：正文说基础类 89.2「比 Meta R-CNN 提高了 8.6」。**89.2 − 80.6 = 8.6**，而 80.6 正是
   图 3-7 里 Meta R-CNN 的 bAP；图 3-6 里 Meta R-CNN 的 bAP 是 80.1，差值是 **9.1**，对不上。
   即正文引用的那组数字，**只能来自图 3-7**。
3. **图题本身有瑕疵**：图 3-6 的中文题是「图 3-6」，英文题却是「**Fig. 3-5** Experiment result
   of 1shot」——编号自相矛盾，说明这两页的图题是后期拼贴的，标错的风险本来就高。

**结论**：正文印刷页 30 那段"1-shot"的论述，实际引用的是 **5-shot** 图的数字。因此：

| | 新类 nAP | 基础类 bAP |
|---|---|---|
| 图 3-6（图题标 1-shot） | **48.8** | 89.2 |
| 图 3-7（图题标 5-shot） | **33.6** | 89.2 |

无论哪张图的图题是对的，**"5-shot 数值正文未给"这一条都不成立**——两张图的数字现在都读到了。
但要注意一个**反直觉的事实**：按图题读，**WSD 上 5-shot 的新类 mAP50（33.6）反而低于 1-shot（48.8），
差 15.2 个点**。这在少样本学习里是异常结果（VOC 上 VAML 是 42.4 → 53.2，正常递增）。
论文对此**没有任何解释**，正文只说"结果表明 VAML 同样是有效的"。**引用时不要用 WSD 的 shot 对比做论据。**
